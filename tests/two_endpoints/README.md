# two_endpoints — runtime 只做一件事:把机器变成两个端点

## 这个场景在测什么

runtime 的职责是把一台机器变成**同一个形状**:一个 `127.0.0.1` 上的 CDP 端点、
一个画面端口。这个场景锁的是这条边界本身:

1. **三种 runtime,一个默认**,选不存在的要说清有哪些。
2. **不可用时抛,不静默降级。** 换成 `process` 等于把页面偷偷挪到你自己机器上跑
   —— 隔离没了,而调用方不知道。所以报错里必须写清换的代价。
3. **端口是部署决定的,不替你换一个。** 被占了就说被占了。
4. **容器那条:变量名全部来自镜像标签。** 同一份代码喂两套标签,产出的变量名
   跟着变、互不串台 —— 这是"加新镜像不用改代码"的唯一证据。
5. **没有标签就硬报错。** 猜错的后果是容器起来了、画面在别的口上,
   而报错指向"连不上"。
6. **CDP 口永远只绑 `127.0.0.1`**,`bind` 只管画面口 —— 它比 API 更底层、
   没有动作日志,能连上就等于绕过整层。
7. `process` 那条**真起真跑**:Chromium + sessiond 起来,lib 连上去点一下。

## 不在这测什么

- **两个具体镜像到底行不行** —— 那要真拉容器,在 [`image_kasmweb/`](../image_kasmweb/)
  和 [`image_jlesage/`](../image_jlesage/)。这里只用假的 docker 验命令怎么拼。
- **`~/.webmuxd.json` 怎么影响 runtime 选择** —— 在 [`installing/`](../installing/)。
