# v2_simple —— 一条完整的路,当样例用

**从 CLI 进。** CLI 存在的意义就是让"起一个浏览器、驱动它、看它变成什么样"
这件事容易做 —— 所以测试应该从那儿进,而不是去 import 内部函数。
一条测试如果只有 import 内部函数才写得出来,那说明这条路人也不好走。

**从观看端看。** 人是从 `/s/<id>/channel/cdp` 那条连接上看的:
画面帧、光标、模式消息都在那儿。要验"人看到了什么",就得从人看的地方看。

## 它做什么

```
webmuxd start --port …          起服务
webmuxd new --id demo           加一个 session
webmuxd goto -t demo baidu      打开百度        → 看到:标题、正文、地址
(观看端)鼠标移到搜索框上        → 看到:光标 default → text
webmuxd type -t demo webmuxd    输入            → 看到:框里有字了
webmuxd key  -t demo Enter      回车            → 看到:搜索结果
```

**每一步都紧跟一句"人看到了什么"** —— 不是"函数返回了什么"。

## 为什么写它

写这一条的过程里挖出四个 bug,每一个的表现都是**什么都没发生,而且不报错**:

1. `Runtime.enable` 全项目没调过 → **光标同步在 JPG/VNC 下从来没工作过**
2. 自窗口把光标上报吃掉了 —— 光标恰恰是被我们自己派发的鼠标移动带出来的
3. `cursor: auto` 落在**空的**输入框上报箭头(没有文字节点可命中)
4. 一次重构把 `_tell_all` 改名成 `_send_all`,漏了光标那一处调用

四个都在"单元测试全绿"的情况下活着。**这就是要有这么一条的理由。**
