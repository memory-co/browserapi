# v2_browser_new_tab —— 那条 tab 条跟不跟得上

## 和 `v2_cli_new_tab` 的分工

| | 验什么 |
| --- | --- |
| [`v2_cli_new_tab/`](../v2_cli_new_tab/) | **后端那张表**:popup 转成 tab、认得爹、焦点不跟过去 |
| 这一条 | **人看到的那条 tab 条** |

[f](../../docs/v2/works/f-tabs.md) 说那条 bar 是"外挂的,和真的那张表是
**同一份数据**,不是副本,因此没有可漂移的东西"。
**这句话以前没有任何一处在验。**

## 一路都是人的动作

```
(画面上点「新闻」)  → tab 条多一个,而且**没切过去**
(点第二个 tab)      → 它 active、地址栏变了、**画面真的换了**
(点 ＋)             → 空白页,三个
(地址栏敲回车)      → 里面那个 tab 真的走了
(点 ×)              → 剩两个
```

**每一下之后同时看两边** —— 人的屏幕上,和 `webmuxd tabs` 里。
两边对不上,"同一份数据"那句话就是假的。

## 几个判据的讲究

- **"画面真的换了"不能只看 `active` 标记。** 标记是 tab 条自己画的,
  它和像素有没有跟过去是两件事 —— 用 `wait_fresh()` 看采样指纹变没变。
- **焦点不跟过去**这条,CLI 那边从后端验过;这儿验的是
  **人确实也看到自己还停在原来那个上**。同一条结论,两个位置各看一次
  才算数 —— 因为中间隔着一层界面。
- **新 tab 刚冒出来时标题是「新标签页」** —— 那一刻 URL 还没定。
  所以断言用的是"条数"和"稍后的标题",不是"立刻有正确标题"。

## 不在这测什么

- popup 转 tab 的规则、`opener` 怎么来的 —— 在
  [`tab_identity/`](../tab_identity/) 和 [`v2_cli_new_tab/`](../v2_cli_new_tab/)
- 画面本身对不对 —— 在 [`v2_browser_modes/`](../v2_browser_modes/)
- **拖动 tab 换顺序** —— 后端有 `/api/tabs/reorder`,观看页上没有这个交互,
  所以没得点
