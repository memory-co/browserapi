# no_desktop — 没有桌面之后,那六类原生 UI

## 这个场景在测什么

v1 里这批东西是"看不见但仍然阻塞" —— 裁 iframe 只是把它挪出可视区,
人换个视图就露出来了,**有兜底**。v2 里它们**根本不会渲染**:screencast 拍的是
页面内容,浏览器自己的 UI 一个像素都不进帧。不拦,页面就静止在那儿,
而人看不出为什么([docs/v2/works/06](../../docs/v2/works/06-no-desktop.md))。

逐类验三件事:**拦得下来、回填得进去、超时不静默**。

1. **`confirm` 挡住页面,回填之后才继续。** 判据不是"我们收到了事件",是
   `window.r` 真的变成了 `true` —— 也就是页面自己动了。
2. **不给 `accept` 就是 400。** 不替用户决定,`accept` 没有默认值。
3. **超时走 dismiss,而且日志里有那一行。** 没人回答最接近的意思是"别做";
   而"页面为什么动了"必须在 scrollback 里查得到。
4. **下载落到 session 目录、改回人看得懂的名字、取得回来。**
5. **文件选择填得进去**,判据是 `input.files[0].name`;
   **上传的名字过一道**,`../../etc/passwd` 不许带路径出去。
6. **权限默认全拒**,显式才给;不认识的权限名要说出来,而不是把 CDP 的原文丢回去。
7. **Basic 认证默认不开。** 测的顺序就是真实顺序:**先撞上 401,再设凭证,再重进** ——
   而不是预先给每个请求上税。凭证不进日志。

## 为什么认证那条是"撞上再设"

拦 auth 的唯一办法是 `Fetch.enable`,而一旦开了,**这个 target 的每个请求都要过
我们的手**再放行。所以它默认不开;不开的时候 401 会照常渲染成服务器返回的那个
页面 —— 是**看得见的失败**,不是页面静止。这和"必须做"那三类的性质不同,
它们不拦就是彻底卡死。

## fixture

`target` 是一个**真的 HTTP 靶子**(aiohttp),因为这三件事没法用 `data:` URL 造:
下载要 `Content-Disposition`、认证要 401 + `WWW-Authenticate`、
文件选择要一个真的 `<input type=file>`。

`live` 另开一条 CDP(`probe`)去读远端页面的真实状态 —— 和
[`pixels_on_a_wire/`](../pixels_on_a_wire/) 一样的姿态。

## 不在这测什么

- **右键菜单 / 拖放 / 打印** —— [06 §5](../../docs/v2/works/06-no-desktop.md)
  里排在"可以晚",有替代路径,还没做。
- **PDF 查看器** —— headless 没有内置查看器,走的就是下载那条路。
