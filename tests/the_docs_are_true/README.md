# the_docs_are_true — 设计稿说的和代码做的必须是同一件事

## 这个场景在测什么

这个项目的设计稿不是"写完就放着"的东西:`docs/v2/works/` 里每一条结论都在被
代码引用、被后来的决定引用。**一条腐烂的结论比没有结论更坏** —— 它看着像依据。

所以这儿钉两样机械可查的:

1. **链接和锚点全都指得到。** 改标题、拆文件、删目录都会悄悄断链,
   而断链在 GitHub 上是静默的(跳到页首,不报错)。
2. **文档里写的数字就是代码里的值。** 28 字节头、ack 额度、画质下限、
   xpra 上行那 6 个包 —— 这些数字是论证的一部分,改了代码不改文档,
   等于让后来的人按一个假前提做决定。

## 不在这测什么

- **文风、结构、有没有写全** —— 那是人看的事。
- **论证对不对** —— 测试证明不了这个。这儿只保证"引用的事实还是事实"。
- 数字的**精确到个位**:像客户端行数那种会随每次修补漂几行的,
  文档里就该写量级([12 §5](../../docs/v2/works/12-xpra-client.md#5-结论自写约-500-行--实际三百出头)),
  不该写死一个数然后靠测试追着改。
