# v2 · DOM 那条腿

**传的是网页本身,不是像素。**

另外两条腿传一张图,判据是"上面有没有东西、多大"。这一条传一棵 DOM,
rrweb 在观看端重建出来 —— `#screen3` 是个 `<div>`,画不进 canvas,
**判据必须换一套**([works/test.md §5.9](../../docs/v2/works/test.md) 里挂了很久的 🔲)。

## 判四件事

| 判什么 | 少了它会漏掉 |
| --- | --- |
| 那棵树长出来了(`nodes` / `title`) | 整条腿没在放 |
| **样式和图也到了**(`sheets` / `images`) | **资源全丢,而上面那条照样绿** |
| 只读是结构性的(`pointer-events` + `inert`) | 人能点进那棵重放的树里 |
| 人的输入到得了里面 | 看得见但用不了 |

## 写它的时候撞出来的三件事

**① 资源全 404。** 地址被改写成根路径 `/api/res`,而路由在 `/s/{sid}/api/res` 下。
百度首页 **25 个请求 0 成功**。重放出来的是一棵**没有样式的**真 DOM ——
节点数、文字、标题**全都对**,只有样式表数和图片数是 0。
**这就是为什么判据里必须有 `sheets` 和 `images`**:只按"有没有内容"判,
这个 bug 一辈子发现不了,人只会觉得"这页怎么这么丑"。

**② 键盘焦点被重放的 iframe 夺走。** rrweb 会把录下来的 focus 事件放出来
(百度一加载就 focus 搜索框),它在 iframe 里调 `.focus()` ——
于是人敲的每一个字都进了那棵**只读**的树,一个都到不了服务端,
**而且一条错都不报**。

`pointer-events: none` 只挡鼠标,焦点是另一条路。挡它要 `inert`,
而且踩了三个坑才对:

- `inert` 设在外面那个容器上**跨不进 iframe**;
- `focusin` 在父文档上**根本不触发**(焦点是从 iframe 内部拿走的);
- rrweb 是 `document.write` 重建的:**`Document` 对象一直没变,而
  `documentElement` 被整个换掉** —— 按文档对象去重就会漏掉换根那一次。

最后是 `MutationObserver` + 按帧复查:那个 iframe 在建完重放器之后
**3 秒多**才被造出来,而页面一静下来就再没有事件进来 ——
拿事件当时机的话,一张不动的页上永远钉不上,**而那正是人最想打字的时候**。

**③ 视频放不了。** 转发那条路不认 `Range`。已定位未修,
记在 [issues](../../docs/v2/issues/DOM-重放里的视频放不了.md);
这条测试里**指名放行**它一条,别的错一条都不许有。
