# 01 · 总体架构

## 1. 分层

```
┌──────────────────────────────────────────────────────────────────────────┐
│  调用方(不属于 browserapi):Agent 循环 / 业务代码 / 评测框架              │

                │ Python lib                           │ HTTP / WS
┌───────────────▼──────────────────────────────────────▼───────────────────┐

│   browserapi (Python SDK)  ←── 同一份 schema ──→  browserapi-server      │
│   · 瘦客户端,默认走 HTTP                          · 鉴权 / 配额          │
```

## 2. 组件职责

### ① 接入层
- **Python SDK (`browserapi`)**:面向使用者的 API。见 [05](05-python-sdk.md)。
  - `remote` 模式:纯客户端,所有能力来自 server。
  - `local` 模式:进程内拉起一个精简控制面(直接用 Docker SDK 起容器,SQLite + 本地目录存轨迹),
    **代码路径与 remote 模式共用**,只是把 HTTP 调用换成进程内调用。
- **`browserapi-server`**:多租户入口,负责鉴权、租户配额、把请求路由到具体会话所在节点。

> 设计要点:SDK **不直连 agentd**。所有流量经控制面,才能保证策略与轨迹不被绕过。
> 例外是画面流(KasmVNC)与事件流(WS),它们通过控制面签发的一次性 token 直连,避免转发大流量。

### ② 控制面
| 模块 | 职责 | 关键设计 |
| --- | --- | --- |
| Session Manager | 容器生命周期 | 预热池(warm pool)消除冷启动;会话-容器 1:1;心跳丢失 → 标记 `unhealthy` 并保留轨迹 |
| Trajectory Store | 轨迹写入与查询 | 写入路径必须是**异步且不阻塞动作执行**,但 Step 关闭时需 flush 保证完整性 |
| Policy Engine | 准入与脱敏 | 动作执行前判定(可拒绝并记 `denied`);观测生成后脱敏(截图打码 / 文本掩码) |
| Event Bus | 事件扇出 | 一份事件同时去:直播订阅者、轨迹落库、指标、审计 sink |

### ③ 操作体容器
基座是 `kasmweb/chrome`,改造点见 [02](02-container-runtime.md)。核心是新增 **`agentd`**:
它是唯一同时握有 CDP 和 KasmVNC 输入通道的进程,因此也是唯一能保证
"Agent 动作与人的动作按同一时间线进入轨迹"的地方。

### ④ 存储
- **元数据 → PostgreSQL**:Run / Step / Action / Event 表,支持按 agent 版本、状态、耗时检索。
- **大对象 → S3 兼容对象存储**:截图(webp)、DOM 快照(gzip)、HAR、可选屏幕录像(webm)。
  内容寻址(sha256),同一页面的重复截图天然去重。

## 3. 部署形态

### 形态 A:嵌入式(`local`)——开发与单机
```
python 进程 ──(Docker SDK)──► operator 容器
       └── 内嵌控制面 + SQLite + ./bapi_runs/ 目录
```
零依赖起步,`pip install browserapi` + 本机 Docker 即可。轨迹落本地,回放器以静态文件方式打开。

### 形态 B:单节点服务(`server`)——小团队共享
```
browserapi-server ──► 本机 Docker 上的 N 个 operator 容器
                 └──► Postgres + MinIO(docker compose 一并起)
```

### 形态 C:集群(`k8s`)——生产
```
Ingress ─► browserapi-server (无状态,多副本)
              │
              ├─► Session Manager ─► K8s Pod(每会话一个 Pod,含 chrome+agentd 容器)
              ├─► Postgres (HA)
              └─► S3
人/浏览器 ─────────────────────────► Ingress(WS) ─► 对应 Pod 的 KasmVNC(token 鉴权)
```
会话有状态(容器绑定),因此路由层需要**会话亲和**:`session_id → node` 映射由 Session Manager 持有,
`browserapi-server` 副本无状态,查表后转发。

## 4. 关键数据流

### 4.1 一次动作的完整路径
```
SDK.click(el)
  → server: 鉴权 + 会话查表
  → control plane: Policy 准入判定
  → agentd: 定位元素(见 03) → CDP 派发 → 等待稳定
  → agentd: 采集 Effect(导航/DOM diff/网络/控制台) + 动作后截图
  → 事件 action.result 发上 Event Bus
  → Trajectory Store 异步落库;调用方同步拿到结果
```

### 4.2 一次观测的路径
```
SDK.observe()
  → agentd: CDP 取 AX 树 + 布局 → 过滤出可交互元素 → 稳定签名计算
  → agentd: 截图 + 按元素 bbox 叠加编号(Set-of-Mark)
  → Policy: 脱敏(按 selector 打码)
  → 返回 Observation;同时作为该 Step 的 observation 存档
```

### 4.3 人接管的路径
```
人点"接管" → control plane: session.control_mode = human
  → agentd: 拒绝后续 Agent 动作(返回 blocked_by_human)
  → 人在 KasmVNC 里直接操作
  → agentd: 仍在采集页面事件 → 轨迹中生成 human_span,含期间的导航/表单提交摘要
  → 人点"交还" → control_mode = agent,Agent 下一次 observe() 看到的是人操作后的新状态
```
这条路径是本设计相对纯 headless 方案的结构性优势:**接管不需要换工具、不需要重建上下文、且同样留痕**。

## 5. 为什么是这个架构(要点)

- **会话与容器 1:1**,不做容器内多会话复用:隔离更强、崩溃爆炸半径小、轨迹归属无歧义。代价是资源开销大,靠预热池和积极回收缓解(见 [07](07-security-and-ops.md))。
- **agentd 在容器内而非控制面直连 CDP**:CDP 是高频、有状态、对延迟敏感的协议,跨网络驱动会显著变慢且脆弱;放在容器内还能把 CDP 端口完全锁死在 loopback。
- **lib 复用 service 的代码路径**:避免"本地能跑线上不行"这一类最消耗人的问题,代价是 lib 引入了一点不必要的抽象层。这个代价是划算的。
- **轨迹写入异步、Step 边界同步 flush**:兼顾动作延迟与轨迹完整性。
