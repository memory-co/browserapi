# `*muxd` 组件规范 v1

判断一个东西**是不是** `*muxd` 组件。不是教程,是判据 —— 每一条都能被检查。

背景和取舍见 [new-interface.md](new-interface.md);这篇只回答"算不算"。

## 0. 术语

| 词 | 指什么 |
| --- | --- |
| **窗**(window) | 人用浏览器打开就能看、能上手的那个 HTTP 端口 |
| **把手**(handle) | 程序驱动它的那个 Python 对象 |
| **契约面** | 用户会直接碰到的那一半 —— 换掉它等于换掉这个组件 |
| **实现面** | 用户碰不到的那一半 —— 随时可以换,换了调用方无感 |
| **session** | 一个有 id、活得比连接久的实例。一个 session 一扇窗 |
| **runtime** | 把一台机器变成"两个端点"的那个东西 |

“必须”= 不满足就不是 `*muxd` 组件。“应该”= 不满足仍然算,但要写明为什么。

---

## 1. 必须

### M1 · 两个端点,别的都不算

对外只提供两样:**一扇窗**(人)、**一个把手**(程序)。
产出这两样的就是合法实现 —— 是不是容器、是不是这台机器,不在契约里。

> 检查:能否用一句话说出这两个端点分别是什么。说不出来就不合规。

### M2 · 窗必须在 HTTP 上

浏览器直接打开,**不需要装任何客户端**。分享一个 session 就是发一个 URL。

裸 TCP 协议(RFB、SSH)可以在**实现面**存在,但不能是窗本身。

### M3 · 必须写明哪一半是契约面,并给出逃生舱

文档里要有一句话点名:**这个是契约,那个是实现细节。**
判据是"**用户会不会直接碰到它**",不是"谁更重要" —— 两半通常都缺不得。

契约面必须有**逃生舱**:绕开这个组件,直接用底层原生工具也能看到同一个东西。

> tmuxd:`tmux -L tmuxd ls` —— 你的 tmux 和它的 tmux 是同一个
> webmuxd:自己拿 DevTools 连上去 —— 看到的和它看到的是同一份 target 表

没有逃生舱的东西是黑盒,不是 `*muxd` 组件。

### M4 · id 幂等

```python
x.session(id="work")   # 建和取是同一件事,像 tmux new -A -s
```

**没有 `create()` 和 `get()` 之分。** 同一个 id 反复调用,返回同一个实例
(同一个 Python 对象,不只是等价对象 —— 否则背后会有两条连接、两份可能不一致的状态)。

### M5 · 端口必须由调用方传,不自动分配

端口是**部署决定的**。替调用方猜一个,只会让配置和实际对不上。
被占了就报"被占了",不换一个。

### M6 · 活得比连接久

关掉网页、退出 Python 进程,里面照常在跑。**这是前提,不是特性。**

### M7 · 库优先

`pip install` 完就能用,**不需要先起任何 server**:

```python
from xmuxd import Xmuxd
x = Xmuxd(...)          # 这行之后就能干活了
```

CLI 和 HTTP 都是套在库外面的壳,不是反过来。

### M8 · 必须能被独立验证

必须有一个 **HTTP 面**,覆盖库的语义,使得**不依赖任何上层、不 import 任何调用方代码**,
就能证明这个组件自己是对的:

```bash
xmuxd new -s demo -p 7900 && xmuxd <动词> -t demo …
curl -s localhost:7900/api/... | jq
```

**这是 HTTP API 存在的唯一理由。** 由此:

- API **不做**库没有的事(反过来可以 —— 纯客户端的便利不必导出)
- API **不必优雅**。读者是调试的人和验证脚本,不是产品用户
- 上层**不该被迫**走 API。正确的用法是 `import`

一个只能在集成环境里被证明是对的组件,还没有真的独立出来。

### M9 · 配置不得改变库的行为

参数从 lib 传。允许有一份记录文件,但它**只记机器的事实**
(哪个二进制在哪、docker 通不通),**不记你的选择**:

- **键在 = 探到了,键不在 = 没探到。** 不写"探不到的默认值"
- **端口、token 这类行为,永远不能来自文件。** `Xmuxd(port=12345)` 必须
  落在 12345,不能因为某人 home 目录里有个文件而跑到别处
- CLI 可以有自己的配置文件(那是人写的),但**库读不到它**

### M10 · 日志是 scrollback

每一步**看到什么、做了什么、结果变成什么样**,按 tmux `history-limit` 那种方式
留着并切割。它是给**人和模型回看**的,不是给机器对账的事件流。

必须:有上限、能回看、人能直接读懂。

### M11 · 不代理那扇窗

只把 URL 报出来。**不做** `/s/<id>/` 这类自己发明的路径、不做 302、不 tee 一份流、
不解析窗那一侧的协议。

怎么摆、要不要套一层网关,是上层的事 —— 组件不替上层做展示决定。

### M12 · 失败必须说清楚

错误要分类,而且分类要指向**不同的下一步**:

| 类 | 意思 | 调用方该做什么 |
| --- | --- | --- |
| 用法错 | 你的代码写错了 | 改代码 |
| 可自愈 | 这次没成,换个说法可能行 | 重试/换参数(agent 循环喂回模型) |
| 平台级 | 底下那个东西出事了 | 报警,别重试 |

报错必须带**这台机器上的那条命令**,而不是泛泛的"请检查环境"。

### M13 · 状态不许撒谎

探不到就说探不到。**装作有,比没有更糟。**

> 没有 Xvnc 时 webmuxd 报 `vnc_url` 为空并明说"这个 session 只有 API 没有画面",
> 而不是给一个连不上的地址。

同理:记录会过期,按它去起、起不来就报错**并让人重跑 install**,不静默重探、
不悄悄兜底。

## 2. 应该

| | |
| --- | --- |
| **S1** | CLI 照着 tmux 的动词来(`new` / `ls` / `kill` / `attach`),别发明新词汇 |
| **S2** | 有一个幂等的 `install`:只探测和安装,再跑一次就是重新探一遍,不需要单独的 `doctor` |
| **S3** | runtime 可插拔,且**不可用时抛错、不静默降级** —— 降级等于偷偷改变了隔离性 |
| **S4** | 日志带 user 署名,分得清哪一步是人做的、哪一步是代码做的 |
| **S5** | 能把日志和产物打成一个包带走(离线可读) |
| **S6** | 命名一致:包名 / CLI 名 `<x>muxd`,环境变量 `<X>MUXD_*`,记录文件 `~/.<x>muxd.json` |

## 3. 明确不在规范里

写出来,免得下次有人往里加:

- **多租户、用户体系、RBAC** —— 组件是单用户的。谁能进,由上层决定
- **鉴权体系** —— 组件只认一个 token(拿着它的人能用),复杂策略是上层的事
- **编排、多节点、调度** —— 组件管一个 session,不管一群
- **UI** —— 窗是别人的产品,画布是上层的产品,组件两个都不做
- **HTTPS 证书** —— 由上层反代或镜像自己解决

## 4. 一致性检查清单

十条,都能实际跑:

```
□ 1  说得出两个端点分别是什么                                    (M1)
□ 2  窗能用浏览器直接打开,没装任何客户端                          (M2)
□ 3  文档里点名了契约面,且逃生舱命令真的能跑通                     (M3)
□ 4  同一个 id 调两次,`a is b`                                   (M4)
□ 5  端口被占时报"被占了",而不是换一个                           (M5)
□ 6  退出 Python 进程后,窗还能打开                               (M6)
□ 7  全新 venv,pip install 后不起 server 就能干活                 (M7)
□ 8  只用 CLI/curl 走完一遍主流程,不 import 任何上层代码           (M8)
□ 9  把记录文件删掉,一切照常(只是每次重探)                       (M9)
□ 10 制造一次失败,报错里有可以直接执行的下一步                     (M12)
```

## 5. 现有成员的符合性

诚实标注,**不合格的地方也列出来**:

| | tmuxd | webmuxd |
| --- | --- | --- |
| 窗 | ttyd 端口 | VNC 端口(KasmVNC / TigerVNC / Selkies) |
| 把手 | `Session.send()` | `Tab.click()` / `observe()` |
| 契约面 | `tmux` | **CDP** |
| 实现面 | `ttyd` | VNC 那一半 |
| 逃生舱 | `tmux -L tmuxd ls` | 自己拿 DevTools 连 |
| M1–M7 | ✓ | ✓ |
| M8 可独立验证 | ✓(HTTP 面是可选 extra,`pip install "tmuxd[server]"`) | ✓ |
| M9 配置不改行为 | ✓(`~/.tmuxd.conf` 是 CLI 的,库读不到;`~/.tmuxd.json` 只记两个二进制的路径) | ✓(没有配置文件) |
| M10–M13 | ✓ | ✓ |
| S3 runtime 可插拔 | 不适用(只有本机一种) | ✓ `process` / `container` / `remote` |

### 5.1 webmuxd 当前**没**满足的地方

- **M13(状态不许撒谎)**:`alive()` 只看容器在不在,不看 API 通不通。
  手工 `docker rm` 会留下孤儿 sessiond 占着端口,而下次 `new` 报的是
  `port_in_use`、**指向端口不指向孤儿**
- **M12(失败说清楚)**:截图超时会让整个 `observe()` 抛 500。
  正确行为是降级成"只给元素表 + 一条 note" —— 观测本来就是尽力而为的
- `discover()` 接管回来的 session 丢掉 localhost 转发,而且没说

这些记在 [works/08 §8](works/08-browser-runtime.md)。**规范的价值就在这儿:
它让"还没做到"变成一个可以被指出来的事实,而不是一种感觉。**
