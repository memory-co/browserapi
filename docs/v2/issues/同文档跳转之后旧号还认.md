# 同文档跳转之后,旧的 `@e1` 还认

**状态**:**未定**(2026-08-22 撞到并量过)。**先不解决** —— 这是个语义问题,
不是 bug,定错了比不定更贵。

## 现象

在百度首页 `snapshot` 拿到搜索框 `@e13`,搜一个词,页面变成
`baidu.com/s?wd=…` —— 地址变了、整屏内容变了。这时候:

```console
$ webmuxd click -t demo @e13
✓ click → textbox ""  1668ms          ← 成功了
```

**旧号还认。** 因为百度那条搜索是**同文档跳转**:`loaderId` 没变,
而那个搜索框是同一个 DOM 节点,一直活着。

跨站导航就不一样了(`loaderId` 变了),这一条我们挡得住:

```console
$ webmuxd goto -t demo https://example.com/
$ webmuxd click -t demo @e13
✗ not_found: @e13(那时是 textbox「」)是上一个页面上的号 —— 页面换过了
```

## 为什么它不是 bug

**那个节点确实还在,确实还是同一个。** 点它没点错任何东西。
按 [`RefTable`](../../../webmuxd/models.py) 现在的定义("号指着那一个 DOM 节点,
节点还在就还认"),这个行为是**对的**。

## 那为什么要记下来

因为**使用者那边的直觉是另一套**:地址变了、屏幕上的东西全换了,
人会说"页面已经不是刚才那个了"。这时候一个还能用的旧号,
可能正好落在他不打算碰的地方。

两种定义各有道理:

| 定义 | `@e1` 意味着 | 代价 |
| --- | --- | --- |
| **节点身份**(现在这套) | 那一个 DOM 节点,还在就还认 | SPA 里翻了三页,旧号可能还指着页头某个按钮 |
| **观测身份** | 那一次 `snapshot` 的产物,页面一动就作废 | SPA 里每点一下都得重新 snapshot,而**页面根本没换** |

agent-browser 是后一种(它文档里写着"页面变了就重新 snapshot"),
但它连跨文档都不挡 —— 那套更松,不是更严。

## 定之前要先量的

1. **`Page.frameNavigated` 在同文档跳转时发不发**(`navigationType`
   是 `sameDocument`)。发的话,"作废"就有一个现成的钩子。
2. **真实的 SPA 上,一次交互会不会频繁触发它** —— 如果每点一下都作废,
   那第二种定义在 SPA 上就是不可用的。
3. 有没有第三种:**号不作废,但 `snapshot` 的输出里标出"它已经不属于当前
   这一屏"**。让调用方自己判,而不是我们替它决定。

## 现在测试里怎么绕开的

[`v2_cli_simple`](../../../tests/v2_cli_simple/) 那条"过期的号点不动"
**先真的 `goto` 到另一个站**,再拿旧号点 —— 这样"过期"是确定的,
走的是跨文档那条路。

原来它是搜完之后直接点,以为搜索就算换页了。那个前提不成立,
于是断言时灵时不灵,还两次把人引去查别处。
**前提不成立的断言,比没有断言更费时间。**
