# 每次确认都要抓一整页,于是号在膨胀

**状态**:**病根修了,语义还没定**(2026-08-22)。

- ✅ 补了 `fill` / `get` / `is` / `count`(照 agent-browser 的源码对齐)。
- ✅ 那条多余的 `click` 删了。
- ✅ **读的动作不再 settle** —— 见 §4.6。
- 🔲 **"同文档跳转之后旧号该不该失效"仍然没定**(§4)。
  但它现在是个小问题了 —— 见 §5 的理由。

**量过的结果**(整条 `v2_cli_simple` 的流,前后对比):

| | 之前 | 现在 |
| --- | --- | --- |
| `snapshot` 次数 | 3 | **1** |
| 整条流发出去的号 | 114 个 | **25 个** |
| 那个搜索框占了几个号 | `e13` / `e32` / `e47` | **`e13` 一个** |
| 一次"确认一个值" | 抓整页,3–15 KB | `get value`,一行 |

起因是 [`v2_cli_simple`](../../../tests/v2_cli_simple/) 里那条"过期的号点不动"
时灵时不灵。查下去发现问题不在那条断言,**在 CLI 的指令集**:
我们比 agent-browser 少了两条命令,而少的那两条正好逼出了一条歪的操作流。

## 1. 原样录下来的一整条流

真跑一遍 `start → new → goto → snapshot → click → type → key → wait`,
每一条的输入、退出码、输出、耗时:

```

  [exit 0, 555ms]
$ webmuxd new --id demo --transport vnc
  ⇢ demo  →  http://127.0.0.1:46295/s/demo/
  ✗        ⚠ 页面跑在这台机器上,**没有隔离**

$ webmuxd goto -t demo https://www.baidu.com/
  ⇢ ✓ goto  https://www.baidu.com/
  [exit 0, 3718ms]
$ webmuxd wait -t demo --css input --timeout 30
  ⇢ ✓ wait_for →  ""  1752ms

  ⇢ {...}  ← 15007 字节 JSON,73 个元素

$ webmuxd click -t demo @e13                  ← 首页拿的旧号,在结果页上点
```

## 2. 这条流里三处不对

### 2.1 那条 `click` 是多余的

`type` 自己会 focus。单独验过:

```console
$ webmuxd type -t d @e13 hello        # 前面没有任何 click
✓ type → textbox ""  1360ms
$ ...框里: [('e38', 'hello', 'textbox#195')]
```

写测试的时候以为"要先点一下才能输入",**那是把观看端的规矩当成了 CLI 的规矩** ——
观看端确实要先 `mousedown` 把焦点交给隐藏的 textarea(IME 要它),
但那是浏览器里那条路,和 `webmuxd type` 无关。白花 1.9 秒。

### 2.2 想确认一个值,只能把整页再抓一遍

流里有**两次 snapshot 纯粹是为了确认**:一次问"框里有字了吗",
一次问"有结果了吗"。它们分别吐了 **2992 字节 / 15007 字节**。

agent-browser 那边这两下是:

```bash
agent-browser get value @e3
agent-browser get count "h3"
```

我们没有 `get`,也没有 `is`。**"问一个元素"这件事在我们这儿只有一个办法:
把整页抓下来自己找。**

### 2.3 于是号在膨胀 —— 同一个节点,五个号

`hint` 字段里那个 `textbox#195` 就是 backendNodeId。同一个节点,
连着抓五次:

```
type 之后         ref=e38    hint=textbox#195
第 1 次 snapshot  ref=e64    hint=textbox#195
第 2 次 snapshot  ref=e90    hint=textbox#195
第 3 次 snapshot  ref=e116   hint=textbox#195
```

**一个元素,五个号,而且五个都还能用。**

因为 `RefTable` 是"只增不重用"——每次 snapshot 给每个元素发一个新号,
旧号不作废。当初那么定是为了**防止旧号悄悄指向另一个东西**([read.md](../cli/read.md)),
那个目的达到了;但它和 §2.2 撞在一起就变成:

> **每确认一次,就多印 26 个号,而且一个都不回收。**

## 3. 和 agent-browser 逐条对

| 这一步 | agent-browser | 我们 | |
| --- | --- | --- | --- |
| 起 + 导航 | `open <url>` | `start` + `new` + `goto` | ⚠️ 有意为之([cli/README](../cli/README.md)) |
| 看页面 | `snapshot -i -c -d 5` | `snapshot -i` | ⚠️ **没有 `-c`/`-d`**,73 个元素压不下来 |
| 填一个框 | `fill @e3 "webmuxd"` | `click` + `type`(而 click 多余) | ❌ **缺 `fill`** |
| 敲键 | `press Enter` | `key Enter` | ✅ |
| **确认一个值** | `get value @e3` | **再 snapshot 一整页** | ❌ **缺 `get`** |
| **确认一个状态** | `is visible @e3` | **再 snapshot 一整页** | ❌ **缺 `is`** |
| 数一类东西 | `get count "h3"` | **再 snapshot 一整页** | ❌ |

**缺的三条(`get` / `is` / `fill`)不是锦上添花** ——
少了它们,"确认"这个动作就只剩"抓整页"一条路,而抓整页会发号。
三件事是连着的:

```
缺 get  →  每次确认都抓整页  →  号在膨胀  →  旧号语义说不清
```

## 4. 顺带那个没定的语义问题

同文档跳转(百度那条搜索就是:地址从 `baidu.com` 变成 `baidu.com/s?wd=…`,
`loaderId` 没变)之后,首页拿的 `@e13` 在结果页上**点成功了**。

**那不是 bug** —— 那个搜索框确实是同一个 DOM 节点,一直活着。
按 [`RefTable`](../../../webmuxd/models.py) 现在的定义("号指着那一个节点,
节点还在就还认"),这个行为是对的。

但**使用者的直觉是另一套**:地址变了、整屏内容换了,人会说
"页面已经不是刚才那个了"。

| 定义 | `@e1` 意味着 | 代价 |
| --- | --- | --- |
| **节点身份**(现在这套) | 那一个 DOM 节点,还在就还认 | SPA 里翻三页,旧号可能还指着页头某个按钮 |
| **观测身份** | 那一次 snapshot 的产物,页面一动就作废 | SPA 里每点一下都得重抓,而**页面根本没换** |

agent-browser 是后一种,但它连跨文档都不挡 —— 那套更松,不是更严。

## 4.5 补完命令之后,那条流长这样

```bash
webmuxd goto     -t demo https://www.baidu.com/
webmuxd wait     -t demo --css input
webmuxd snapshot -t demo -i            # ← 只有这一次
webmuxd fill     -t demo @e13 webmuxd  # 一条,顶掉 click + type
webmuxd get value -t demo @e13         # 确认,不抓整页
webmuxd is visible -t demo @e13        # 答案在退出码里
webmuxd key      -t demo Enter
webmuxd wait     -t demo --url-contains webmuxd
webmuxd get count -t demo --css h3     # 数结果,不抓整页
```

**三次 snapshot 变成一次。** 号也就不再一批一批地印。

顺手实测的:

```console
$ webmuxd fill  -t d @e13 webmuxd     ✓ type → textbox ""  1500ms   [exit 0]
$ webmuxd get value -t d @e13         webmuxd                        [exit 0]
$ webmuxd is visible -t d @e13        true                           [exit 0]
$ webmuxd is checked -t d @e13        false                          [exit 1]
$ webmuxd get box   -t d @e13         [238, 195, 771, 28]            [exit 0]
$ webmuxd get attr  -t d 新闻 href     http://news.baidu.com          [exit 0]
$ webmuxd get count -t d --css h3     0                              [exit 0]
$ webmuxd get title -t d              baidu.com                      [exit 0]
```

> **踩到一处 argparse:** `get value -t demo @e13` 里那个 `-t demo` 把位置参数
> 劈成两段,argparse 只肯把 `nargs="+"` 配给连着的一段,剩下那个成了
> "unrecognized arguments"。而 `get <种类> <目标>` 这个顺序是照
> agent-browser 来的,不该为了绕开这个限制去改它 —— 所以在 `main()` 里用
> `parse_known_args` 自己收尾。

## 4.6 补完之后又量出来一件:读的动作在等页面稳下来

对齐完再录一遍,发现 `get` 比 `snapshot` 慢了六倍:

```
snapshot(不走 act)   417ms
get value            2430ms
is visible           1983ms
get count            1707ms
```

**差的是 `settle`。** `get` / `is` / `count` 走 `act`,而 `act` 每个动作之后
都要等页面稳下来 —— 在真实站点上那是一秒多(§ [network_idle 那条](#))。

但**读没有"做完",没什么可等的**。它什么都没改。
`snapshot` 之所以快,恰恰是因为它不走那条路。

> **同一件事两个价钱,那是路走错了,不是它本来就贵。**

于是 `READ_ACTIONS = {extract, count}` 跳过 settle:

```
get value    2430ms → 340ms
is visible   1983ms → 360ms
get count    1707ms → 360ms
click        2490ms → 2490ms   ← 它真的改了页面,该等
```

`wait_for` 没放进去:它等到条件成立之后再让页面稳一下是有意的 ——
调用方下一步多半要动手。

## 5. 语义那一条:为什么现在可以先放着

补完命令之后,"一次交互抓一次快照"成立了,于是号的膨胀停了。
那时候再看 §4 那个语义问题,它的分量小了很多:

**一次交互只有一份号,旧号还能不能用就不那么要紧了** ——
因为下一次交互开始时本来就会重新 snapshot。

反过来,如果当初先动号的语义(比如同文档跳转也作废),会让 §2.2 更糟:
**每确认一次都要重抓,而重抓之后号又全变了。**先修病根是对的顺序。

### 还没做的

1. **`snapshot -c` / `-d`。** agent-browser 有,我们没有 ——
   但那两个是**树形输出的旋钮**,而我们出的是一张平表,压不了同样的东西。
   我们有的是 `-s`(划范围)和 `--max`(截断)。
   **73 个元素怎么压**这个问题还在,只是解法不一样。
2. **`get` 进不进行为流。** 现在它走 `extract` 动词,所以进了。
   它是"读"而[动词表](../works/i-agent-surface.md#2-动词表)管的是"做" ——
   一个 agent 的日志里塞满 `get value` 会不会把真正做过的事冲淡,还没量过。

   > 两种说法都站得住:读**不是**"做过的事",不该进;但"它看了这个值
   > 然后做了那个决定"恰恰是排查 agent 时最想知道的。
   > **要么给它一个标记让 `log` 能滤掉,要么想清楚为什么不给。**
3. `hover` / `clear` / `select` / `check` / `upload` 后端都有,CLI 还没摆出来
   ([act.md](../cli/act.md))。

## 6. 测试里现在怎么绕开的

[`v2_cli_simple`](../../../tests/v2_cli_simple/) 那条"过期的号点不动"
**先真的 `goto` 到另一个站**,再拿旧号点 —— 这样"过期"是确定的,
走的是跨文档那条路。

原来它是搜完之后直接点,以为搜索就算换页了。那个前提不成立,
于是断言时灵时不灵,还两次把人引去查别处。
**前提不成立的断言,比没有断言更费时间。**
