# 切走了,那条像素通道还占着

**状态**:**未修**(2026-08-22 发现并量过)。
**影响**:切到 JPG 的人在自己看不到的地方一直付着 xpra 那份带宽
(实测 807 kbps)。功能不受影响,所以**它不会自己暴露出来**。

## 现象

VNC 切到 JPG 之后,**xpra 那条通道还在推帧** —— 人看的是 `<img>`,
而 `<canvas>` 那条上的像素照收不误,收完扔掉。

用 Playwright 按通道数了一下每 3 秒收到的帧:

| 当前显示 | `/channel/cdp` | `/channel/xpra` |
| --- | --- | --- |
| VNC | 0 | 5 |
| **JPG** | 5 | **5** ← 这一份是白花的 |
| 切回 VNC | 0 | 5 |

VNC 那条腿实测 **807 kbps**。也就是说切到 JPG 的人,
在自己看不到的地方**一直付着这份带宽**。

## 为什么

[`session-view.ts`](../../../webmuxjs/client/src/viewer/session-view.ts)
的 `applyMode()` 里,rrweb 那条是关的:

```js
rrweb.close();          // 切走了就别占着那条连接
```

xpra 那条没有对应的一行。`startXpra()` 建的那个 `XpraClient`
一旦建起来就活到页面关掉为止。

## 修它要想清楚的

**不是删一行的事**,因为关掉之后切回来要重新握手:

- 重连要多久?xpra 的握手是几个来回,期间人看到的是空白 ——
  **那正是[另一条](../works/test.md)刚说清的"已连接≠画出来了"**
- `applyMode()` 里 `if (!xpra) startXpra()` 这个判断要跟着改成
  "关掉时把 `xpra` 置回 null",否则切回来又会走进那个
  [刚修掉的 bug](../../../tests/v2_browser_modes/) 的老路
- 要不要给个宽限期(切走 N 秒后才断),让来回切的人不用每次都等握手

## 怎么发现的

写 [`tests/v2_browser_modes/`](../../../tests/v2_browser_modes/) 的时候
顺手用 `page.on("websocket")` 按通道数了帧 —— **本来是为了确认切换有没有
真的换掉上游**,结果发现旧那条根本没停。

**这类东西只有真浏览器量得到**:服务端那边两条通道各自都是"正常工作"的。
