# VNC 下,页面自己以为的宽度比画面多一像素

**状态**:**认了**(2026-08-22,随 0.12.0 的像素对齐一起)。
**影响**:VNC 下 `snapshot` 报的 `viewport` 是画面的 `W+1 x H+1`。
画面本身是对齐的(人看到的没有缝),但**页面右下最外圈那一像素落在桌面外**,
而元素坐标是按 `W+1` 排的。JPG 和 DOM 不受影响。

## 现象

```console
$ # 观看端的 stage 是 1260x774
$ webmuxd --json snapshot -t demo | jq .viewport
{"w": 1261, "h": 775}
```

画布是 1260x774,页面是 1261x775。

## 为什么

chrome **不接受一个正好等于屏幕大小的窗口**。在同一个 1260x774 的桌面上
扫了一遍 `Browser.setWindowBounds`:

| 要的宽 | 到手 |
| --- | --- |
| 1258 | 1258 |
| 1259 | 1259 |
| **1260**(= 屏幕) | **1259** ← 只有这一个退了一像素 |
| 1261 | 1261 |

于是只有两条路:

- 要 `W` → 到手 `W-1`,画面右下各露一条 1 像素的桌面底色。**有缝,看得见。**
- 要 `W+1` → 窗口盖满桌面,多出来的那一像素落在桌面外。**没缝,看不见。**

选了后者([`screen.py: _fill_screen()`](../../../webmuxd/screen.py))。

## 为什么不用 setDeviceMetricsOverride 钉回去

试过,**画面直接变成一整块纯色,一帧内容都没有**。VNC 那条腿的画面是页面被
真的画进 X 窗口再抓下来的;套一层模拟视口之后渲染就走进了那条模拟路径,
X 窗口里不再有东西。

## 什么时候值得再看

- 有人报"元素坐标差一像素点不中"。今天没有 —— 差一像素落在任何一个可点
  元素的边缘之外。
- 找到一条既能盖满桌面、又不改页面排版宽度的路。目前没找到。
