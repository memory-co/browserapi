# words · 一件事一个词

**一句话**:这一份**不是数据,是规则** —— 三个词,加上"怎么归一、
默认选哪个、哪种要有头浏览器"。

## 1. 三个词

```
JPG   一张一张的图,什么都显示得出来      实现是 screencast
VNC   像远程桌面,连续、跟手              实现是 xpra
DOM   传的是网页本身,字最清楚、最省流量   实现是 rrweb
```

**使用者看到的是左边那三个,右边那三个只出现在日志和代码里**
([c §9.1](../works/c-view.md#91-使用者看到的是三个词))。

这条是产品规矩,不是命名偏好:`screencast` / `xpra` / `rrweb` 说的是
"我们怎么做到的",而使用者要选的是"我要什么样的画面"。

## 2. 它比"一堆常量"多的东西

| | 规则 |
| --- | --- |
| `canon()` | 旧名字继续认(`screencast`/`cdp`/`jpeg` → `jpg`),但**不再回传给使用者**。不认识就返回 `None`,**不猜、不兜底** |
| `MODES` 的顺序 | **顺序即优先级**:能用 VNC 就用 VNC,退而 JPG,再退 DOM。**只在"默认选哪个"时用到** —— 运行时切换永远是人选的,不自动降级 |
| `available_in()` | 这台 session 上**能切到**哪几种。`remote` 那条够不着对端的 X 显示 —— **少一个选项不是降级,是那条路上的全集** |
| `needs_headed()` | 哪一种要一个真实的 X 显示 |
| `mode_choices()` | 给 API / 界面用的那张表 —— **界面不该自己再写一遍这些字** |

`ViewMode` 里那四个字段(`label` / `blurb` / `when` / `impl`)也是这个意思:
**"什么时候选它"这句话只写一次**,CLI 的帮助、API 的响应、观看页右下角
那块牌子全从这儿取。

## 3. 为什么它不该待在 models 里

因为它一个"数据"都不是。`canon` 是归一策略,`MODES` 的顺序是产品决策,
`available_in` 是环境规则 —— 它们只是碰巧和三个字符串常量住在一起。

而混在 993 行中段的后果很具体:

> **想加第四种画面的人,不知道要改几处。**

分成一个文件之后,那个答案就是"这个文件里的每一处",而且它只有 55 行。

## 4. 三层贯通靠什么守着

[`the_layout_holds/`](../../../tests/the_layout_holds/) 里那条
「一件事一个词」:CLI、`serve.py`、`api.py` 三个面里,**不许出现实现名**
(`screencast` / `xpra` / `rrweb`)。

这条今天就在跑,拆文件不改变它 —— 但拆完之后**该改哪儿**变得显然了。
