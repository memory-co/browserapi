# models · 跨边界的数据,以及那四条边界不是一回事

**一句话**:`models.py` 的规矩只有一条 —— "**它会不会跨过一条边界**" ——
而这条规矩把**四种不同的边界**当成了同一种,还顺手收了五样根本不跨边界的东西。

> 这一篇是**设计稿,还没落地**。它讲的是那个文件今天为什么难读,
> 以及要拆成什么样才守得住它自己写在开头的三条规矩。

## 1. 那个文件今天什么样

993 行,36 个定义,`__all__` 里 33 个名字。**它不是"太长",是"混"** ——
长度只是症状。

它开头写着三条规矩:

1. **只有数据,没有行为。** 一旦它开始 import `cdp.py`,它就不再是模型层了
2. **不 import 本项目任何东西**(除 `exceptions`)—— 保证它永远在最底下
3. **凡是出现在 HTTP / WS 上的形状,必须在这儿定义一次**

三条都对。问题是**第 1 条今天不成立,第 2 条那个"除 exceptions"正是第 1 条
破了的证据**,而第 3 条把四种性质完全不同的契约收进了同一个盒子。

## 2. "边界"是四种东西,它们连"改了之后谁会疼"都不一样

| 这一类 | 跨的是什么 | 另一头是谁 | 改了会怎样 | 今天谁在验 |
| --- | --- | --- | --- | --- |
| 下行消息 + 帧头 | **语言** | [`messages.ts`](../../../webmuxjs/client/src/protocol/messages.ts) 里那份**第二个实现** | 两边不一致 → **观看页静默不工作** | [`two_implementations/`](../../../tests/two_implementations/) 拿 fixture 对拍 |
| REST 形状 | **HTTP** | SDK / CLI / 别人写的 UI | 少个字段 → 调用方 `KeyError` | [`the_http_face/`](../../../tests/the_http_face/) |
| 记录文件 | **时间** | 上一次 `webmuxd install` 写下的那份 | 格式变了 → 靠 `FACTS_VERSION` **整份作废重探** | [`installing/`](../../../tests/installing/) |
| 三个词 | **三层** | CLI 的帮助、API 的字段、观看页上那块牌子 | 词不一致 → 使用者看到两个名字 | [`the_layout_holds/`](../../../tests/the_layout_holds/) 那条「一件事一个词」 |

四类里:

- **只有第一类有第二个实现**(所以只有它需要对拍)
- **只有第三类有版本号**(`FACTS_VERSION = 3` —— 别的都没有,也不该有)
- **只有第四类根本不是数据**,是一张词表加几条规则(`canon` 认旧名字、
  `MODES` 的顺序即优先级、`needs_headed` 说哪种要有头浏览器)

把它们摆在一个文件里,等于宣称它们是同一种东西。而**一个改动会打到谁**,
这四类的答案完全不同 —— 改 `Cast` 要同时改 TS 那边,改 `BrowserFact`
只需要让老记录作废,改 `JPG` 这个词要三层一起改。

## 3. 里面有五样根本不跨边界

判据用文件自己那句话就够:**没有 `to_json`,就没跨过 JSON 那条边界。**
全文 18 个类有 `to_json`,下面这几个一个都没有:

| | 多大 | 为什么它不是模型 |
| --- | --- | --- |
| `RefTable` | **67 行 / 3 个方法 / 抛 4 种 `NotFound`** | 有状态、有策略、会抛 —— 它是个服务 |
| `SessionInfo` | 19 行 | `detail` 是 `dict[str, Any]`,而且**里面装着活的子进程**(`detail["_xpra"]` 是 xpra 那个 `Popen`) |
| `PageDigest` | 7 行 | 只有 `act.py` 用,从不出门 |
| `Quality` | 5 行 | 只有 `quality.py` 用;出门的是 `QualityChanged`,不是它 |
| `PackageFamily` | 12 行 | 只有 `install.py` 用 |

### 3.1 `RefTable` 是第 2 条规矩破掉的**唯一**原因

第 2 条写的是"不 import 本项目任何东西(**除 `exceptions`**)"。
那个括号看着像个无害的例外。它不是 ——

```
models.py 里 `NotFound` 的全部用处:
  _not_found()   ← 一个专门造异常的函数
  RefTable.get() ← 四处 raise
```

**除此之外一处都没有。** 也就是说:**`models.py` 之所以需要那个例外,
完全是因为它装了不该装的行为。** 把 `RefTable` 和 `_not_found` 搬走之后,
第 2 条就不再是一句自觉,而是**结构上做不到** —— 那个文件一行项目内 import 都没有。

一条规矩要么有东西守着,要么迟早不成立。这一条恰好可以变成前者。

## 4. 还有一处从文件里看不出来的事

`to_json` 有 18 个,`from_json` 只有 8 个。

**这个不对称本身是对的** —— 下行消息是单向的:服务端写、TS 读,Python 永远
不需要读回来,给 `Hello` 加一个 `from_json` 是纯粹的死代码。

但**从这个文件里看不出哪个缺失是设计、哪个是漏**。`ActionResult` 没有
`from_json`,是因为它也是单向的,还是因为写的时候没想到 SDK 要读回来?
今天得去翻调用方才知道。

拆开之后这件事自己就说清楚了:**`wire.py` 里一律没有 `from_json`(它是单向的),
别处一律成对。** 这条能直接变成一句断言。

## 5. 结论:扁平的四个文件,外加搬走五样

**不建 `models/` 包。** [j §5](../works/j-layout.md#5-依赖方向扁平之后层要靠规矩守)
那条"没有子目录了,层靠规矩守"仍然成立;加一层目录只是把问题挪进目录名里,
而且会让层表里那一行变成一个特例。

```
第 0 层   models.py   跨 HTTP 的形状     —— 别人说 "models" 时指的就是它  约 370 行
          wire.py     跨语言的下行消息   —— **这一份有第二个实现**        约 100 行
          facts.py    跨时间的落盘记录   —— 带 FACTS_VERSION             约 110 行
          words.py    一件事一个词       —— 三个词的词表和规则            约  55 行
```

四个文件**都不 import 本项目任何东西**,包括 `exceptions`。

搬走的五样,各回各家:

| 搬什么 | 搬去哪 | 因为 |
| --- | --- | --- |
| `RefTable` `Ref` `_not_found` | **新 `refs.py`**(第 2 层) | 有状态、有策略、会抛;而且它是 models 唯一的项目内依赖(§3.1) |
| `SessionInfo` | `sessions.py` | 它握着活进程 |
| `PageDigest` | `act.py` | 不跨边界 |
| `Quality` | `quality.py` | 不跨边界 |
| `PackageFamily` | `install.py` | 不跨边界 |
| `FrameHeader` | **`frames.py`** | 它的编解码本来就在那儿。**形状和编解码分两个文件,是把一件事切成了两半** |

> 最后那一条顺带消掉一条依赖:今天 `frames.py` 要 `from webmuxd.models import FrameHeader`,
> 搬完就不用了。

### 5.1 为什么是这四个名字

- `models.py` **保留原名**。它仍然是最大的一类,而且"models"这个词在这个
  项目里已经指代过它 —— 改名要付的是所有人重新学一遍的钱,买到的只是对称。
- `wire.py` 对应 [e1 · 线上格式](../works/e1-wire-format.md);
  **它是四个里唯一需要"两边一起改"的**,单独一个文件就是给这件事一个提醒。
- `facts.py` 对应 [d · 装](../works/d-install.md) 里那份记录。
- `words.py` 对应「**一件事一个词,三层贯通**」那条 —— 它今天散在 models 中段,
  而它其实是这个项目的一条产品规矩,不是一堆常量。

## 6. 拆完之后,那三条规矩第一次有东西守着

拆本身不产生价值,**能被守住才产生价值**。三条各配一句断言,
放在 [`the_layout_holds/`](../../../tests/the_layout_holds/)(不跑浏览器,永远会跑):

| 规矩 | 怎么验 |
| --- | --- |
| **只有数据,没有行为** | 第 0 层那四个文件里,类的方法只许是 `to_json` / `from_json` / dunder。多一个都红 |
| **不 import 本项目任何东西** | 那四个文件的项目内 import 必须是**空集**(今天 models 有一行,正是 §3.1 那个例外) |
| **单向的才允许没有 `from_json`** | 有 `to_json` 没 `from_json` 的类,只许出现在 `wire.py` |

第一条是关键。今天"只有数据,没有行为"这句话**一处代码都没有守着它** ——
而 `RefTable` 就是这么长到 67 行的:它不是有人决定把服务塞进模型层,
是它一点一点长出来的,**中间没有任何一步会红**。

## 7. 迁移

一次机械改名,不留别名。

**不做"`models.py` 里 re-export 一遍"的过渡层** —— 那等于同一个概念两处
能 import 到,而这个文件存在的全部理由就是"一个概念一处定义"。
过渡层会活很久,因为它不疼。

顺序:

1. 先加 §6 那三条断言(它们会红,红的正是要搬的那几样)
2. 搬 `RefTable` / `Ref` / `_not_found` → `refs.py`,`FrameHeader` → `frames.py`
3. 拆 `wire.py` / `facts.py` / `words.py`
4. 搬剩下四样各回各家
5. 层表(`the_layout_holds` 的 `LAYERS`)加上新名字 —— **加文件就要想清楚它在第几层**

每一步跑全量。第 1 步之后到第 4 步之前,那三条断言是红的 —— **这是对的**,
它们说的就是"还没搬完"。
