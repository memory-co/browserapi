# models · 跨边界的数据

**一句话**:`models.py` 的规矩只有一条 —— "**它会不会跨过一条边界**" ——
而这条规矩把**四种不同的边界**当成了同一种,还顺手收了五样根本不跨边界的东西。

> **设计稿,还没落地。** 讲的是那个文件今天为什么难读,以及要拆成什么样
> 才守得住它自己写在开头的三条规矩。

## 1. 它今天什么样

993 行,36 个定义,`__all__` 里 33 个名字。**它不是"太长",是"混"** ——
长度只是症状。

文件开头写着三条规矩:

1. **只有数据,没有行为。** 一旦它开始 import `cdp.py`,它就不再是模型层了
2. **不 import 本项目任何东西**(除 `exceptions`)—— 保证它永远在最底下
3. **凡是出现在 HTTP / WS 上的形状,必须在这儿定义一次**

三条都对。问题是:第 1 条今天不成立,第 2 条那个"除 `exceptions`"**正是第 1 条
破了的证据**([not-models](not-models.md#2-那个除-exceptions-的例外)),
而第 3 条把四种性质完全不同的契约收进了同一个盒子。

## 2. 「边界」是四种东西

它们连**改了之后谁会疼**都不一样:

| 这一类 | 跨的是什么 | 另一头是谁 | 改了会怎样 | 谁在验 | 详见 |
| --- | --- | --- | --- | --- | --- |
| 下行消息 + 帧头 | **语言** | JS 那边**第二个实现** | 两边不一致 → 观看页**静默不工作** | [`two_implementations/`](../../../tests/two_implementations/) 对拍 fixture | [wire](wire.md) |
| REST 形状 | **HTTP** | SDK / CLI / 别人的 UI | 少个字段 → 调用方 `KeyError` | [`the_http_face/`](../../../tests/the_http_face/) | [http](http.md) |
| 记录文件 | **时间** | 上次 `webmuxd install` 写下的那份 | 格式变了 → 整份作废重探 | [`installing/`](../../../tests/installing/) | [facts](facts.md) |
| 三个词 | **三层** | CLI 的帮助、API 的字段、观看页那块牌子 | 使用者看到两个名字 | [`the_layout_holds/`](../../../tests/the_layout_holds/) | [words](words.md) |

四类里:

- **只有第一类有第二个实现** —— 所以只有它需要对拍,也只有它改起来要两边一起动
- **只有第三类有版本号**(`FACTS_VERSION = 3`)—— 别的都没有,也不该有
- **只有第四类根本不是数据** —— 它是一张词表加几条规则

摆在一个文件里,等于宣称它们是同一种东西。

## 3. 结论:扁平的四个文件,外加搬走五样

**不建 `models/` 包。** [j §5](../works/j-layout.md#5-依赖方向扁平之后层要靠规矩守)
那条"没有子目录了,层靠规矩守"仍然成立;加一层目录只是把问题挪进目录名里,
还会让层表里那一行变成一个特例。

```
第 0 层   models.py   跨 HTTP 的形状     别人说 "models" 时指的就是它   约 370 行
          wire.py     跨语言的下行消息   **唯一要两边一起改的**         约 100 行
          facts.py    跨时间的落盘记录   带 FACTS_VERSION               约 110 行
          words.py    一件事一个词       三个词的词表和规则              约  55 行
```

四个文件**都不 import 本项目任何东西**,包括 `exceptions`。

搬出去的五样在 [not-models](not-models.md)。

### 3.1 为什么是这四个名字

- **`models.py` 保留原名。** 它仍然是最大的一类,而且这个词在项目里已经
  指代过它 —— 改名要付的是所有人重新学一遍的钱,买到的只是对称。
- `wire.py` 对应 [e1 · 线上格式](../works/e1-wire-format.md)。
  单独一个文件,是给"改它要两边一起改"这件事一个提醒。
- `facts.py` 对应 [d · 装](../works/d-install.md) 里那份记录。
- `words.py` 对应「**一件事一个词,三层贯通**」—— 它今天散在 models 中段,
  而它其实是一条产品规矩,不是一堆常量。

## 4. 拆完之后,那三条规矩第一次有东西守着

拆本身不产生价值,**能被守住才产生价值**。三条各配一句断言,放在
[`the_layout_holds/`](../../../tests/the_layout_holds/)(不跑浏览器,永远会跑):

| 规矩 | 怎么验 |
| --- | --- |
| **只有数据,没有行为** | 第 0 层那四个文件里,类的方法只许是 `to_json` / `from_json` / dunder。多一个都红 |
| **不 import 本项目任何东西** | 那四个文件的项目内 import 必须是**空集** |
| **单向的才允许没有 `from_json`** | 有 `to_json` 没 `from_json` 的类,只许出现在 `wire.py`([wire §3](wire.md#3-单向是这一份的特权)) |

第一条是关键。今天"只有数据,没有行为"这句话**一处代码都没有守着它** ——

> `RefTable` 不是有人决定把服务塞进模型层,是它**一点一点长到 67 行的**,
> 中间没有任何一步会红。

## 5. 迁移

一次机械改名,**不留过渡别名**。不做"`models.py` 里 re-export 一遍"的过渡层 ——
那等于同一个概念两处能 import 到,而这个文件存在的全部理由就是"一个概念一处定义"。
过渡层会活很久,因为它不疼。

1. 先加 §4 那三条断言。**它们会红,红的正是要搬的那几样**
2. 搬 `RefTable` / `Ref` / `_not_found` → 新的 `refs.py`;`FrameHeader` → `frames.py`
3. 拆出 `wire.py` / `facts.py` / `words.py`
4. 剩下四样各回各家([not-models §1](not-models.md#1-五样不跨边界的))
5. 层表(`the_layout_holds` 的 `LAYERS`)加上新名字 ——
   **加文件就要想清楚它在第几层**

每一步跑全量。第 1 步之后到第 4 步之前那三条是红的 —— **这是对的**,
它们说的就是"还没搬完"。
