# facts · 跨时间的那一份

**一句话**:`~/.webmuxd.json` 里那份记录 —— 它跨的不是网络,是**时间**:
另一头是上一次 `webmuxd install` 的自己。

## 1. 里面有什么

| | 记什么 |
| --- | --- |
| `MachineFacts` | 整份记录 |
| `BrowserFact` | 用哪个浏览器,以及它是**我们下的**还是机器上本来就有的 |
| `XpraFact` | xpra 在哪、**它自己的解释器**是哪个、`--xvfb=` 传什么 |
| `RrwebFact` | DOM 那条腿的记录器:版本 + 落在哪 |
| `FACTS_VERSION` | **格式的版本号** |

`XpraFact.python` 单记一条不是学究气:`xpra` 是带 shebang 的脚本,用的是
系统的 Python,而 webmuxd 很可能装在一个 venv 里 —— `python3-pil` 要装进
**它那个**里面。

## 2. 它是唯一一类有版本号的

`FACTS_VERSION = 3`。别的三类都没有,**也不该有**:

- 跨 HTTP 那份([http](http.md))**只加不减**,所以永远兼容,不需要版本
- 跨语言那份([wire](wire.md))两边一起改,版本号帮不上忙
- 三个词([words](words.md))本来就是一张表

只有这一类的另一头**改不了** —— 那份文件是过去的自己写的,而过去已经过去了。
所以它的规矩是:

> **格式变了,老记录就当没有** —— 重新探,而不是猜字段。

猜字段的下场是"读到一个半新半旧的记录,而且每个字段单看都合法"。
整份作废虽然要重探一次,但它**只有一种结果**。

## 3. `None` 不是默认值,是"没探到"

这条是整份记录的语义基础:

```
键在   = 探到了
键不在 = 没探到
```

所以 `to_json()` 里 `None` 的字段**一个都不写**(那就是 `_drop_empty` 的用处),
`from_json()` 里探不到就返回 `None` 而不是一个空对象。

写一个猜的值进去,下次读的人分不清"探到了是空"和"没探过" ——
而这两件事要做的事完全相反:前者该报错,后者该去探。

## 4. 它为什么不该和 REST 那份混在一起

两者都是"带 `to_json` / `from_json` 的 dataclass",看着一模一样。
但**改一个字段的后果差得很远**:

| | 加个字段 | 删个字段 |
| --- | --- | --- |
| REST([http](http.md)) | 安全 | **别人的代码 `KeyError`** |
| 记录(这儿) | 老记录读不到它,**按 `None` 处理** | 版本号 +1,老记录整份作废 |

放一起就会有人拿 REST 的直觉去改记录、或者反过来。分开之后,
打开 `facts.py` 看见头一行那个 `FACTS_VERSION` 就知道这儿的规矩不一样。
