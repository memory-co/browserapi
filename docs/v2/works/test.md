# 测什么,怎么测

**这一篇写测试场景的设计**,不写具体断言 —— 断言在
[`tests/`](../../../tests/) 里,每个场景自己的 `README.md` 说清它盯着什么。

这一篇要回答的是上一层的问题:**这个项目值得测的到底是哪几件事,
从哪个口子进去测,以及什么不该测。**

## 1. 判据:代码错了它会红吗

一条断言只有在**代码错了它会红**的时候才值钱。

反例是删掉的那个 `the_docs_are_true/` —— 它检查文档里的链接、锚点、
和文档里抄下来的数字。它红的时候多半是**有人改了个标题**,
而不是代码错了。**那是给文档做的 lint,不是给这个项目做的测试。**

按这条判据,这个项目真正值得测的是**交界处**:

| 交界 | 错了会怎样 |
| --- | --- |
| 我们 ↔ Chromium | 假设变了而我们不知道(`openerId`、`targetCreated` 那类) |
| 我们 ↔ 观看的人 | 画面出不来、点了没反应,而且**不报错** |
| 我们 ↔ 调用方 | 退出码、错误码、动词表变了而调用方不知道 |

第二条是最难测也最要命的一条:**这一面的 bug 长得都一样 ——
什么都没发生,而且不报错。** 单元测试全绿,人打开一看是黑的。

**三条都该由端到端那几条守着,而不是各开一个贴着代码的场景。**
理由是同一条判据:一个断言如果只在"某个内部函数的形状变了"时红,
它守的是形状不是行为 —— 而形状本来就该能改。

> 写 [`v2_cli_simple`](../../../tests/v2_cli_simple/) 挖出四个这样的 bug,
> 每一个都在"单元测试全绿"的情况下活了很久。**这就是这一套存在的理由。**

## 2. 命名:`v2_<面>_<场景>`

**"面"是从哪个口子进去的**,这是这套测试的第一级分类 ——
因为同一件事从不同的面进去,验到的东西不一样。

| 面 | 从哪进 | 它独有的价值 |
| --- | --- | --- |
| `v2_cli_*` | 真起 `python -m webmuxd` 一个进程 | argv 解析、退出码、stdout —— **装完能不能用** |
| `v2_browser_*` | Playwright 起一个**真的**浏览器,当最终用户 | **人在画面上的操作真的到里面了吗**;以及**观看页自己报没报错** |
| `v2_refs` 这类 | 纯数据,不起浏览器 | 一条规矩的语义,快到可以随便跑 |

后面还可能有 `v2_api_*`(直接打 HTTP)和 `v2_sdk_*`(`import webmuxd`)——
**但只在它们能验到 CLI 验不到的东西时才开**。同一条路测三遍不是覆盖率,是维护成本。

## 3. 三条规矩

写在 [`tests/v2kit.py`](../../../tests/v2kit.py) 开头,`v2_*` 每一条都照这个来:

1. **动作从 CLI 进,而且真起一个进程。**
   `[sys.executable, "-m", "webmuxd"]`,不是 `from webmuxd.cli import main`。

   > in-process 调函数测不出 argv 解析、退出码、stdout 那一层 ——
   > 而那一层出过事:入口点写错过一次,装完 `webmuxd` 根本起不来,
   > 全套单元测试没有一条发现。
   >
   > 也**不用 PATH 上那个** `webmuxd`:它指向 site-packages,可能是上一版。
   > **测的是这棵树,不是机器上碰巧装着的东西。**

2. **观察也从 CLI 进。** `snapshot` 给的 `@e1` 就是页面结构,不往页面里塞 JS。

   > 这条是被逼出来的。改造 `v2_cli_simple` 的时候,"找到搜索框"这一步
   > 只能写 `document.querySelectorAll('input,textarea')` ——
   > **那不是逃生舱用得克制,那是一个缺的命令被 JS 顶掉了。**
   > 于是有了 [`snapshot`](../cli/read.md)。
   >
   > 反过来说也成立:**一条测试如果非塞 JS 不可,先问是不是缺了个命令。**

3. **"人看到了什么"一律从一个真的浏览器来。**

   画面画没画出来、光标变没变、窗口一改会怎样、**观看页自己有没有报错** ——
   只有真浏览器看得见。

   > **别在 `v2_cli_*` 里接 WebSocket 看协议消息。** 一开始那么干过:
   > cli 那两条各挂着一段"连上 `/channel/cdp`,数帧、看光标消息"。
   > 不好 —— **「我们往那条线上发了什么」和「人看到了什么」是两件事**,
   > 而混进画面断言的那条 cli 场景,既说不清自己在验什么,
   > 坏了也不知道该往哪边查。
   >
   > 协议那一层由 [`pixels_on_a_wire/`](../../../tests/pixels_on_a_wire/)
   > 贴着字节验,那是它该待的地方。

### 一条命令有两份输出,是两种契约

```python
cli.run(...)   # 只看退出码 —— 大多数命令
cli.out(...)   # 人读的那份 stdout —— capture / url
cli.api(...)   # `--json` 那份,它是 API 的原始响应,解析它不算"解析输出"
```

给脚本用的是退出码。人读的那份会变,别断言它的措辞。

### 等那件事发生,不等一个秒数

**睡固定时长是在赌网速** —— 赌输了就是一条时灵时不灵的测试,
而那比没有更坏。用 `wait --css` / `--text` / `--url-contains`。

等不了的地方(比如"又开了一个 tab")用轮询顶上,**但要在注释里说明
这是 CLI 的缺口**,并且记进 [cli/](../cli/) 对应那一篇。

## 4. 现有场景

| 目录 | 面 | 盯着什么 |
| --- | --- | --- |
| [`v2_cli_simple/`](../../../tests/v2_cli_simple/) | cli | 一条完整的路:起服务 → 开 session → 打开百度 → 搜一个词 → 看到结果。走 **VNC(有头)** |
| [`v2_cli_new_tab/`](../../../tests/v2_cli_new_tab/) | cli | 点 `target=_blank` 弹出来的**是个 tab**:认得爹、焦点不跟过去。走 **JPG(无头)** |
| [`v2_cli_session/`](../../../tests/v2_cli_session/) | cli | **两个 session 各干各的**:号不串、日志不串、关掉一个另一个照常能用 |
| [`v2_refs/`](../../../tests/v2_refs/) | 数据 | `@e1` 的规矩:四种失败各说各的话、只增不重用、**不跨文档** |
| [`v2_browser_simple/`](../../../tests/v2_browser_simple/) | browser | **一个真人打开观看页会撞上什么**:点一下、敲几个键、拉小窗口,里面真的动了,而且观看页一条错都没报。见 §5 |
| [`v2_browser_modes/`](../../../tests/v2_browser_modes/) | browser | **换画面,而且换得回来**(VNC → JPG → VNC),顺带是 **VNC 那条腿唯一的端到端验证**。见 §5.5 |
| [`v2_browser_reconnect/`](../../../tests/v2_browser_reconnect/) | browser | **网抖一下,画面回不回得来**。见 §5.6 |
| [`v2_browser_new_tab/`](../../../tests/v2_browser_new_tab/) | browser | **那条 tab 条跟不跟得上** —— 人点链接/tab/`×`/`＋`/地址栏,每一下**两边都看**。见 §5.7 |
| [`v2_browser_pixel_align/`](../../../tests/v2_browser_pixel_align/) | browser | **人的窗口多大,里面那个浏览器就多大**。JPG 和 VNC 各验一遍。见 §5.8 |

**两条 cli 场景分走两条画面腿,是故意的:**

| | VNC(有头) | JPG(无头) |
| --- | --- | --- |
| `/channel/cdp` 上的帧 | **一帧都没有**,像素走 `/channel/xpra` | **帧就从这儿来** |
| 光标 | `text`(I 型) | `pointer`(手型) |
| 为什么必须是这条 | 百度给无头弹图形验证码 | 没有搜索,不会撞验证码 |

合起来才算把画面这一面盖住。**一条测试顺带验一条腿,不额外写一条。**

## 5. `v2_browser_*`:一个 session,加一个真人

### 5.1 它要回答的问题

前面所有场景都是**我们自己**发命令、**我们自己**读结果。
中间那一段 —— **人在画面上点的那一下,到底有没有到里面** —— 一条都没验。

而那一段恰恰是这个项目最不能出错的地方:
[`b`](b-input.md) 那八步、[`c`](c-view.md) 那两条像素腿、
[`e`](e-client.md) 那个客户端,全在这一段里。

### 5.2 形状:一个 session,加一个**真的**浏览器

```bash
webmuxd server start --port P
webmuxd new   --id demo                       # 只有这一个 session
webmuxd goto  -t demo https://www.baidu.com/
webmuxd attach -t demo --print-only           # → http://127.0.0.1:P/s/demo/
```

另一边是 **Playwright 起的一个真浏览器**打开那个地址,然后:

```python
who.click(box)        # 在画面上点里面那个搜索框
who.type("web")       # 敲字
who.resize(900, 700)  # 把窗口拉小
```

判据仍然从 CLI 那边读:`snapshot -t demo` 里那个框有字了、
`log -t demo --user human` 记下了那一下。

> **试过"第二个浏览器也是一个 webmuxd session",不对。** 三条理由:
>
> 1. **用自己的栈去测自己的栈是循环的** —— 截屏那条腿坏了,
>    "被观看的"和"观看的"会一起坏,而测试照样绿
> 2. 要测的是**最终用户会撞上什么**,那第二个浏览器就得是用户那种浏览器,
>    不是我们栈里的另一个 headless session
> 3. 用户那边最要紧的一类信息 —— **观看页自己报的错** ——
>    我们的 CLI 今天根本读不到([cli/debug.md](../cli/debug.md) 里
>    `console` 还是 🔲)。而 Playwright 一行 `page.on("pageerror")` 就有了

**那条"不引入第二套工具"的洁癖是错的。** 它把"我们的工具好不好用"
和"用户会不会出问题"混成了一件事 —— 而这一条测的是后者。

### 5.3 坐标怎么换算

观看端的正向映射写在 [`input/mods.ts`](../../../webmuxjs/client/src/input/mods.ts):

```
inner = (client − rect.topLeft) × (cast ÷ rect.size)
```

测试算它的逆,三个输入都在真浏览器那边现取:

| | 从哪来 |
| --- | --- |
| `rect` | `page.locator("#screen").bounding_box()` |
| `cast` | **`<img>` 的 `naturalWidth/Height`** —— 实际推过来那张图有多大 |
| `inner` | `snapshot -t demo` 里那个元素的 bbox(这一半仍从 CLI 来) |

> **`cast` 不是 session 名义上的分辨率。** 而且它**跟着观看的人走** ——
> 1280×900 的窗口打开,里面那个 session 就变成 1245×791。
> 这本身是一条判据([§5.4](#54-判据按重要性排) 第 5 条)。

### 5.3.1 顺带修的一个真 bug

画面那三个元素原来在可访问性树里既没 role 也没名字,
`<img id="screen" alt="">` 尤其糟 —— **空 `alt` 的意思是
"这张图没有信息,读屏跳过它"**,而它恰恰是整页唯一有信息的地方。
一个用读屏软件的人打开观看页,什么都听不到。

```html
<img    id="screen"                      alt="浏览器画面">
<canvas id="screen2" role="img" aria-label="浏览器画面" hidden>
<div    id="screen3" role="img" aria-label="浏览器画面" hidden>
```

**改完之后这条主张是可测的**:
`page.get_by_role("img", name="浏览器画面")` 找得到就算数 ——
一条 a11y 修复从"改了一行"变成"有断言守着"。

### 5.4 判据(按重要性排)

1. **点下去里面真的动了。** `snapshot -t demo` 前后不一样 ——
   这是整条链路的端到端证明,没有别的测法。
2. **行为流里记的是 `human`,不是 `api`。**
   这是[形态那条](../cli/README.md#三条对齐)的结构性收益,
   而且是把 CDP 端点直接交出去的方案**做不到**的事 ——
   人点的那一下和程序发的 `Input.dispatchMouseEvent` 在线上是同一种字节。
   **不验这一条,`log --user` 就只是文档里的一句话。**
3. **观看页一条错都没报。** `page.on("pageerror")` + `console.error` ——
   **这一条只有真浏览器验得了**,而它是"用户说打开是白屏"时的第一手信息。
4. **像素真的落地了。** `<img>` 的 `naturalWidth` 不是 0,
   而且和状态条上那行「帧 W×H」对得上。

   > **判据别用 fps。** 第一版写的是"`0 fps` 不该出现",一跑就红 ——
   > 那是**瞬时速率**,页面加载完不再产帧,本来就该掉到 0。
   > **那是对的行为,是断言错了。**
5. **窗口一改,里面跟着变。** 这是"用起来像个普通浏览器"里最容易坏的一条:
   分辨率跟着观看的人走,不是写死的。
6. **只读连接点不动。** —— 🔲 还没验,见 §5.9。

### 5.5 换画面那条:判据是颜色,不是尺寸

[`v2_browser_modes/`](../../../tests/v2_browser_modes/) 盯 VNC → JPG → VNC。

**它是被一个 bug 逼出来的。** 切回 VNC 那一步曾经什么都不做 ——
按钮点了画面纹丝不动,**没有报错,console 也是干净的**。
原因是"显示哪个元素"那三行只写在 `startXpra()` 里,而它被 `if (!xpra)`
挡着(切走时那条连接没关)。**两件事缠在一起,就漏了一条路。**

判据用**颜色**:把当值的那个画面元素画进一张离屏 canvas,采样数颜色,
`colors <= 1` 就是白屏。这么绕的理由有两条:

1. JPG 是 `<img>`(有 `naturalWidth`),VNC 是 `<canvas>`(**没有**)——
   只判尺寸的话 VNC 下永远是 0,一条测试要么写不了要么写成两套
2. **一整块死白也是有尺寸的**

顺带这也是 **VNC 那条腿唯一的端到端验证**:`v2_cli_simple` 走 VNC,
但只验到"那条通道接得上"。

#### 三条想当然,都红过

| 以为 | 实际 |
| --- | --- |
| JPG 总是跟着人的窗口走 | **有头这条路上不是** —— 浏览器跑在 xpra 的 X 显示里,窗口是那个显示定死的 |
| 在 JS 里用 `offsetParent` 挑哪个元素可见 | VNC 下挑中了**隐藏着的那个 `<img>`**,量到上一条腿的旧图。**两处各判一次,就会有一处判错** |
| 元素 bbox 存下来能复用 | 敲完一个词百度首页的搜索框从 y=195 挪到 y=25,拿旧坐标点到了别处 —— **而且不报错**。跟 `@e1` 那条规矩是同一件事:**页面变了就重新 snapshot,测试自己也得守** |

### 5.6 断线重连:判据是新帧在流

[`v2_browser_reconnect/`](../../../tests/v2_browser_reconnect/) 掐一条通道,
看它自己回不回得来。**最终用户最常撞的一类** —— 合盖、切 WiFi、进隧道。

它挖出来的是一处不对称:

| | 断了之后 |
| --- | --- |
| `/channel/cdp` | 1 秒后自己爬回来 |
| `/channel/xpra` | **报个 `closed` 就完了** |

而代码里**没有一句话说这是有意的** —— 是漏了。VNC 下网抖一次,
画面永远停在最后一帧,只能刷新页面。顺带还有一处:那个灰掉画面的
`dead` 类**加上去就再没摘过**。**好起来了要说,不只是坏了要说。**

#### 怎么把网掐了

**Chromium 自己的断网模拟对 loopback 上已经建好的 WebSocket 一律无效** ——
`context.set_offline(True)` 和 CDP `Network.emulateNetworkConditions`
两个都试过,状态一直是「已连接」。

用 Playwright 的 `route_web_socket` 从中间接过来,说掐就掐。
副产品是 `who.channels`:**每重连一次多一条**,数它就知道断没断过。

#### 判据:让里面动一下,看画面跟不跟

断线前那一帧还留在画布上,**颜色数一模一样**。所以判"回来了"要看
**新帧在不在流**:恢复之后 `goto` 到另一页,画面的采样指纹得变。

> 挑那"另一页"也踩了一下:第一版用 example.com → example.org,
> 两张渲染出来一模一样。VNC 那条于是一动不动 —— **xpra 只发变化的区域,
> 页面没变就没有帧**;而 JPG 那条却过了,因为每帧重编码带点噪声。
> **一个判据在两条腿上一真一假,那是判据没写对,不是腿有问题。**

### 5.7 那条 tab 条:同一份数据,两个位置各看一次

[`v2_browser_new_tab/`](../../../tests/v2_browser_new_tab/) 和
[`v2_cli_new_tab/`](../../../tests/v2_cli_new_tab/) 是一对:

| | 验什么 |
| --- | --- |
| cli 那条 | **后端那张表**:popup 转成 tab、认得爹、焦点不跟过去 |
| browser 这条 | **人看到的那条 bar** |

[f](f-tabs.md) 说那条 bar 是"外挂的,和真的那张表是**同一份数据**,
不是副本,因此没有可漂移的东西"。**这句话以前没有任何一处在验。**
验它的办法只有一个:**每一下之后两边都看**。

一路都是人的动作:画面上点 `target=_blank`、点 tab、点 `×`、点 `＋`、
地址栏敲回车。

#### 两条讲究

- **"画面真的换了"不能只看 `active` 标记。** 标记是那条 bar 自己画的,
  和像素有没有跟过去是两件事 —— 用 `wait_fresh()` 看采样指纹。
- **同一条结论,两个位置各看一次才算数。**「焦点不跟过去」cli 那条从后端
  验过了,这儿还要再验一次 —— **因为中间隔着一层界面**,后端不切不等于
  人看到的没切。

#### 又踩了一次同一个坑

**条目先有,URL 后到。** 新 tab 刚冒出来那一刻标题还是「新标签页」、
地址栏是空的。CLI 那边的 `Cli.wait_tabs` 早就为这个加过等待,
浏览器这边**又踩了一次** —— 两个位置各有一份"等它落定"的逻辑,
就会有一处忘写。

### 5.8 像素对齐:三个数要同时相等

ttyd 把终端调成你窗口那么大。**这一条我们也得做到** —— 不然人拉大窗口
只是把同一张图放大,越拉越糊。

判据不是"画面变了",是三个数**同时**相等:

    人窗口里给画面留的那块地  ==  画面元素占的地  ==  帧本身的像素

少验哪一个都漏掉一整类错:只比前两个,一张 1024 宽的图撑在 1260 的框里
也算"对齐"(其实是拉伸);只比后两个,元素被 CSS 缩过一道也看不出来。

再加一条**页面自己以为的宽度** —— 截图可以是对的而页面按另一个宽度排版,
那时候人看到的图没问题,agent 拿到的元素坐标却是另一套。

两个数字上的讲究:

- **尺寸里掺奇数**(1151x641)。全用偶数的话,一个 `//2*2` 的舍入 bug
  可以一路蒙混过去。
- **页面故意选不滚动的那个**(example.com)。`cssVisualViewport` 是
  **不含滚动条**的 —— 拿会滚的页面来验"页面自己的宽度",
  量的不是对齐,是滚动条宽度(15 像素)。第一版就是拿百度写的,红在这儿。

VNC 那条链上**每一环都真断过一次,而且断得都没有声音** ——
那五环记在 [c §8.4](c-view.md#84-像素对齐人的窗口多大里面就多大)。
写这条测试的过程就是把它们一个个找出来的过程:**没有这条测试,
"人拉窗口画面不跟"只会是一句体感,指不到任何一行代码。**

VNC 下断言的不是"页面宽度等于画面",是"等于画面 +1" —— 那一像素是
chrome 的一条硬规则,认了,记在
[issues](../issues/VNC-下页面比画面宽一像素.md)。**测试写的是真实情况,
不是我们希望的情况**;哪天那条规则变了,它会红。

DOM 那条腿这一轮不验:它重放的是 DOM,尺寸的判据是另一回事(见 §5.9)。

### 5.9 还没想清楚的

  而那是 `mousedown` 时做的。所以"人敲键"之前必须先有"人点一下" ——

## 6. 老场景怎么办

### 已经删掉的

| | 为什么 |
| --- | --- |
| `the_docs_are_true/` | 检查文档链接和文档里抄的数字。**给文档做的 lint,不是给这个项目做的测试** —— 它红的时候多半是有人改了个标题 |
| `cli_shell/` | 测的东西对(退出码是接口、`new` 幂等),但它 **in-process 调 `main()`**。`v2_cli_*` 从真进程进,把它验的那几条连同更多一起验了 |
| `errors_are_a_contract/` | 量的是异常类和错误码的映射 —— **形状,不是行为**。真正要保的是"退出码 4 意味着定位失败",那一条 `v2_cli_simple` 在验 |
| `chrome_facts/` | 量的是 CDP 的行为(四种开 tab 全带 `openerId`)。**这一条有代价**:换 Chromium 大版本时它是唯一会红的东西,现在只能靠 `v2_cli_new_tab` 端到端地发现 |
| `session_identity/` | 测 SDK 那三个对象的语义。`v2_cli_session/` 从 CLI 那面接过了"两个 session 互不影响"这一半;**另一半(对象幂等、属性读内存、`act()` 不抛)真的没了** —— 要补该开 `v2_sdk_*`,别塞回 cli 那一面 |

> 最后那条**记下来,别当没发生**:`chrome_facts` 是唯一一个"直接问浏览器
> 我们的假设还成不成立"的场景。删掉之后,同一个问题只会以
> "`v2_cli_new_tab` 挂了"的形式出现 —— **能发现,但要多花一步定位。**

### 剩下的怎么迁

`tests/` 下还有十来个老场景。判据只有一条:**从 CLI 进能不能验到更多。**

- 能 → 迁。多验一层进程边界,而且顺手变成能贴进 shell 的实录
- 不能 → 留着。像 [`pixels_on_a_wire/`](../../../tests/pixels_on_a_wire/)
  量的是二十八字节的帧头 —— CLI 上根本没有那个东西的出口

**一条也别为了迁而迁。**
