# h · 浏览器从哪来

**一句话**:**runtime** 是「浏览器从哪来」这件事的抽象 ——
它只回答一个问题:**这个 session 的 CDP 端点从哪来**。
本机起一个进程,或者你给一个。**画面不在它的契约里**,那是我们自己产的。

> 之所以需要这个词,是因为它下面的两种情况差别很大(起一个进程 / 连一个现成的),
> 而**它上面的所有代码不应该看见这个差别** —— §1 那条边界就是这个意思。

## 1. 契约只剩一条

```
runtime 的产出:一个 CDP 端点   http://<host>:<port>
```

产出这一样就够了。画面不是它的义务 —— 那是用这个端点自己产的([c](c-view.md))。

于是 runtime 只剩两种,而两者的区别只是**这个端点是我们起的,还是你给的**:

```
        ┌── process   本机起一个浏览器进程
runtime ┤
        └── remote    你给一个 CDP 端点
                            │
        ────────────────────┼────────  ← 边界:一个 CDP 端点
                            │
                    webmuxd 自己产画面
```

**这条边界之上没有一行 `if runtime == …`。** 上面所有的东西 ——
帧、输入、tab、原生 UI、日志 —— 只看见一个 CDP 端点。

## 2. 不碰容器

一个容易被提的方案是:起一个带浏览器的容器。**不做。**

判据是这个项目一贯的那句:**tmux 会做这个吗?** tmuxd 不会 `docker run` 一个 tmux。

容器原本承担三件事,现在逐个清算:

| 容器为什么曾经必要 | 现在 |
| --- | --- |
| 里面有现成的浏览器 **+ 桌面 + VNC** | 画面自己产,桌面不需要([c](c-view.md)) |
| 使用者不必自己装浏览器 | **`webmuxd install` 下一个**([d](d-install.md)) |
| 隔离 | **只剩这一条 —— 而它不是 webmuxd 的活** |

**方向是反过来的:把 webmuxd 放进容器里,而不是让它去起容器。**

```dockerfile
FROM python:3.12-slim
RUN pip install webmuxd && webmuxd install
```

这是一个部署决定,不是我们的参数。因此 `image=` / `network=` 这类参数一并不存在。

### 2.1 说清楚:隔离是真的没了

默认情况下**页面跑在你自己的机器上**,没有网络与文件系统隔离。
这一条不因为"默认"就说得轻一点。要隔离,两条路:
把 webmuxd 装进容器,或者用 `remote` 连一个别处的浏览器(§4)。

## 3. `process`:起一个进程

```bash
<install 下来的浏览器> --remote-debugging-port=<free> --user-data-dir=<profile>
```

一个进程,秒起,是 server 的子进程,`kill-server` 时跟着结束。

启动参数随像素来源不同([c](c-view.md)):`/channel/cdp` 那条以无头方式启动;
`/channel/xpra` 那条是有头的,由 xpra 拉起,并带 `--kiosk` 与软件 GL 参数。

### 3.1 root 下自动关闭沙箱,但必须说出来

默认不加 `--no-sandbox` 是通行做法,因为它关闭的是一项安全特性。
**这里有一个例外:检测到 root 就自动加上。**

**① root 加沙箱没有可运行的配置。** Chromium 直接拒绝启动:

```
Running as root without --no-sandbox is not supported. See crbug.com/638180.
```

这不是可选项。报错让使用者自己去查,等于**把一个无解的选择退回去**,
而且那个开关的名字他不可能猜到。

**② 我们推荐的隔离方式默认就是 root。** §2 建议把 webmuxd 放进容器,
而那三行 Dockerfile 跑出来就是 root。若 root 一律拒绝,推荐的做法自己走不通。

**但「不静默关闭安全特性」这条保留** —— 它变成一条必须打印的提示:

```
⚠ 检测到 root —— Chromium 在 root 下必须 --no-sandbox 才能启动(crbug 638180),
  已自动加上。**沙箱是关闭的**;需要沙箱请换非 root 用户运行。
```

### 3.2 启动失败时,把浏览器自己那句话带出来

浏览器的 stderr 必须留存。丢弃它,启动失败时我们只能说「手工跑一遍看报什么」——
**等于把排查工作原样退回去,而答案本来就在我们手里。**

现在 stderr 落到工作目录下的日志文件,失败时取最后几行、**去掉前缀**后并入错误:

```
✗ 浏览器启动了但 CDP 没有监听:Running as root without --no-sandbox
  is not supported. See https://crbug.com/638180.
  完整日志在 …/chrome.log
```

去前缀这一步不能省。Chromium 每行形如:

```
[206402:206402:0818/205945.649553:ERROR:…/zygote_host_impl_linux.cc:102] 真正的话
```

**前面那一串对使用者没有意义,保留它只会把真正的信息挤出屏幕。**

同理,xpra 那条路上还要分清是「xpra 自己退出了」还是「xpra 在跑但浏览器没起来」——
**首句指错方向,后面的日志再全也没用。**

### 3.3 一个 session 一个浏览器

| | |
| --- | --- |
| 一个 session | 一个浏览器进程、一个 profile、一个 CDP 端点、一个对外端口 |
| 需要两个 | 起两个。profile 目录不同即互不相干 |

浏览器的单实例锁在 `user-data-dir` 里,给不同的 profile 目录即可,
一台机器可以跑很多个。

这与 tmux 的差别在于:**浏览器不是终端,一个浏览器进程本身就是一个隔离单位** ——
cookie、登录态、缓存都在 profile 里。因此 session 无法像 tmux 那样复用一个 socket。

## 4. `remote`:你给一个 CDP 端点

不启动任何东西,只记下那个端点:

```python
sess = web.session(id="cloud", port=7900,
                   runtime="remote", cdp="wss://chrome.example.com?token=…")
print(sess.view_url)      # http://127.0.0.1:7900/  ← 画面由我们产,浏览器是他们的
```

这条路径的价值在于:**云浏览器服务通常只提供 CDP**,画面那一半要么没有,
要么是他们自己的产品界面。而我们只需要一个 CDP 端点 ——

> **给一个只有 CDP 的云浏览器,配上人能看、能上手的画面。**

它同时是「没有开箱隔离」的出口:对 webmuxd 而言这些是同一件事,
因为它只看见一个 CDP 端点 —— 云浏览器服务、另一台机器上的浏览器,
或者一个自行启动的容器。**隔离在最后那条上,由你决定。**

### 4.1 `remote` 上像素只有一条来源

`/channel/xpra` 需要采集**浏览器所在机器上的 X 显示**,而 `remote` 只有一个
CDP 端点,那台机器我们碰不到。因此这条路径上 `/channel/cdp` 是**唯一可能**的
像素来源 —— 它在这里是默认,而这不是降级。

显式要求 xpra 会报错,不会静默改用另一条 —— 静默替换会使人误判画质来源。

## 5. 绑哪个地址:默认只绑回环

**参数名是 `--bind`,不是 `--host`。** CLI 中 `--host` 已表示「连哪台机器」
(客户端一侧),再用它表示「绑哪个地址」必然冲突。

```bash
webmuxd new --id work --port 7900                  # 只绑 127.0.0.1
webmuxd new --id work --port 7900 --bind 0.0.0.0   # 对外,并打印警告
```

**默认必须是回环**,理由是那个端口上的东西变了:它不再是纯 API,
而是**打开即可直接操作浏览器**的画面口。

对外是使用者的决定,但必须显式,且会打印:

```
⚠ 画面口绑在 0.0.0.0 —— 这台机器网络可达的人,拿到 token 即可操作这个浏览器
```

## 6. 端口由你给

**端口是部署决定的,替你猜一个只会让配置与实际不符。**
一个 session 一个端口,画面与 API 在同一个上。

## 7. 边界之外仍然不碰

| | |
| --- | --- |
| 编排 / 扩缩容 / 健康检查 | 那是部署的事 |
| 代理池、指纹、验证码 | 那是另一个产品的事 |
| 多租户、配额、计费 | tmux 不做这些 |
