# i · 给 agent 的操作面,和一条人机共用的行为流

**一句话**:agent 能做的事是一张**封闭的动词表**;人和 agent 做过的事进**同一条流**,
每条标明是谁做的。这两件事是同一件事的两面 —— 操作面定义了能发生什么,
行为流记录了发生了什么。

## 1. 三层操作面

操作按**改变什么**分层,这决定了它走哪条接口:

| | 例子 | 改变的是 | 走哪儿 |
| --- | --- | --- | --- |
| **session 级** | 起一个、停一个、分享 | 进程与端口 | CLI / 库 |
| **tab 级** | `open` `close` `activate` `reorder` | session 的 tab 表 | `/api/tabs` |
| **页面级** | `click` `type` `goto` … | 某一个页面内的状态 | `/api/act` |

**`open` 在中间那层,不在动词表里。** 这一点常被找错,值得说明理由:

> `act` 是**按 tab 串行**的 —— 一个 tab 一个执行器,遇错即停。
> 而「开一个新 tab」的结果是**另一个 tab**,串行语义对不上。

## 2. 动词表

| 组 | 动词 |
| --- | --- |
| 导航 | `goto` `back` `forward` `reload` `stop` |
| 指点 | `click` `hover` `scroll` |
| 输入 | `type` `clear` `key` `select` `check` `upload` |
| 读取 | `extract` `count` `wait_for` |
| 逃生舱 | `js` |

> `extract` 那一个动词底下挂着一张 mode 表:
> `text` / `html` / `value` / `attr` / `table` / `box` /
> `visible` / `enabled` / `checked`。CLI 上它们长成 `get` 和 `is`
> ([cli/read.md](../cli/read.md))。
>
> **一个动词一张表,不是九个动词** —— "从一个元素上取一个值"是一件事。
> `count` 单独一个,因为它**不落到单个元素上**。

三条性质:

**① 动词是封闭集合,`js` 是唯一的逃生舱。** 封闭才能被日志记录、被权限约束。
`js` 那条要在日志里**显眼** —— 它绕过了上面所有的语义。

**② 定位失败不是异常,是候选。** 按人看得见的文字定位,分档匹配;
有歧义时返回候选而不是替你挑一个。写 agent 循环时要把候选喂回模型自我纠正,
而不是被异常打断。

> 这与「把模型放进 SDK 里、由它重试」是不同的取舍:
> **谁来承担猜错的后果。** 这里把决定权留在外面。

**③ 每个动词都要能回答「做完之后页面变成什么样」。** 否则调用方只能再截一张图
自己比对,而那正是 agent 最容易出错的地方。

### 2.1 还缺的动词

对着 agent 实际会撞上的东西看,这几项目前只能用 `js` 硬写:

| 缺的 | 为什么值得单列 |
| --- | --- |
| `drag` | 拖拽排序、滑块验证。`js` 合成的事件常被判定为非人操作 |
| `switch_frame` | 跨 iframe 的页面越来越多 |
| 「点击并等待下载完成」 | 下载有专门的事件与端点([g](g-native-ui.md)),但没有这个组合动作 |
| `wait_for_navigation` | 现在的 `wait_for` 等的是元素 |

**判据不是「有没有用」,而是:不做的话,是不是只能掉进 `js` 逃生舱。**
掉进去就意味着那一段不再被日志和权限看见 —— 那才是真正的代价。

## 3. 读的那一面:一张图、正文,和一张元素表

**动词表管"能做什么",这一节管"能看到什么"。**

```
GET /api/screenshot   → image/webp
GET /api/text         → text/plain
GET /api/snapshot     → 元素表,每样带一个 @e1
```

### 3.1 第三样砍过一次,又回来了

那时它叫 `GET /api/observe`:一次调用回一整包 —— 筛过的元素表、编好的号、
一次观测的 id、盲区 notes、页面信息、截图、正文。砍它的理由是:

> 那不是一个多路复用器该有的东西,那是**一套关于 agent 该怎么用浏览器的意见**。
> 意见的问题不在于它错,而在于**它会过时,而使用者绕不开它**:
> 那 150 个上限、"可交互优先"的那张 role 表、编号的稳定性保证 ——
> 每一条都是一个会被将来的模型推翻的赌注。

**这个理由站不住,而且是被一条测试逼出来的。**

`tests/v2_cli_simple` 要全程走 CLI。写到"找到搜索框"那一步走不下去了 ——
只能塞一段 `document.querySelectorAll('input,textarea')` 进去。
那不是逃生舱用得克制,**那是一个缺的命令被 JS 顶掉了**。

回头看那套"意见":它此刻仍然在跑。每次 `click("登录")` 都要先
`Accessibility.getFullAXTree`、按 `INTERACTIVE_ROLES` 筛一道、量 bbox
([`locate.snapshot`](../../../webmuxd/locate.py))。
**藏起来没有让赌注变小,只是让它没法被人调。**

真正该做的是[把旋钮交出去](../cli/read.md):

```bash
webmuxd snapshot -t demo -i           # 只要能点能填的
webmuxd snapshot -t demo -s "#main"   # 只看这棵子树
webmuxd snapshot -t demo --viewport --max 50
```

**判据仍然是那句"tmux 会做这个吗"** —— 而这一次的答案是会:
`capture-pane` 就是"把里面的东西抓出来",一张图、正文、和一张元素表
是同一件事的三种粒度。当初答错,是因为把"抓出来"和"替你判断该看哪些"
混成了一件事。

> 有人会问:那 `a §7` 说的"语义要另开一条路去 DOM 里取"呢?
> **那条仍然成立,而且就在动词表里** —— `click("登录")` 就是拿 DOM 语义做的,
> `extract` 也是。区别在于**语义服务于动作,而不是被打包成一份报告端出去**。

### 3.2 编号这次是怎么解决的

老方案是 `{"element": 12, "observation": "obs_..."}` —— 靠一个观测 id 挡陈旧编号。
砍掉观测之后那道挡板没了落点,于是编号也一起砍了,理由是
**留着键而挡不住,比没有这个键更坏**。

这一版换了个挡法:**号只增不重用**([`models.RefTable`](../../../webmuxd/models.py))。

```
snapshot  →  @e1 … @e12
click @e5 →  页面变了
snapshot  →  @e13 … @e20      ← 不是又一批 @e1
```

不需要"这个号属于哪次观测"这条元数据了 —— **号本身就是全局唯一的**。
拿过期的号去点,只可能落到两种结果上:表里没这个号,或者节点已经不在页面上。
两种都报错,而且[话不一样](../cli/read.md#三种失败分开说)。
**"点到另一个东西且不报错"这条路被结构性地堵死了**,不再依赖谁记得带上 id。

agent-browser 那边是重来的(它文档里明写着第二次 `@e1` 指着另一个元素)。
这一条我们不跟 —— 词汇对齐它,**安全性上不跟着它降**。

所以循环变成这样:

```python
while True:
    d = my_llm(goal=goal, image=tab.screenshot(),
               page=tab.snapshot(interactive=True).as_prompt(),
               history=sess.log(limit=5))
    if d.done: break
    r = tab.act(d.actions, note=d.thought)   # 动作里写 {"ref": "e7"}
    if not r.ok:
        feedback = r.candidates              # 拿 role + name 重试(§2②)
```

### 3.3 顺带丢掉的一样,得说清楚

`notes` 没有了 —— 那几句"页面有 3 个 iframe,其中 1 个跨域读不到"、
"页面还在加载"。它是**关于那一次观测的**元数据,没有"一次观测"就无处可挂。

**这是这次砍掉的真实代价**,不是零。原来那条理由仍然成立:
不说盲区,模型会把"没看见"当成"不存在"。将来要补回来,该补在**动词的结果里**
(`after` 已经在回答"做完之后页面变成什么样"),而不是重新开一个报告端点。

## 4. 一条行为流,每条标明是谁做的

日志是一个 `log.jsonl`,序号与事件流共用一个计数器。**关键是它记录了 `user`**:

```jsonc
{"seq":41,"kind":"action","user":"api",  "action":"click","target":{"label":"登录"},"ok":true,"ms":210}
{"seq":42,"kind":"action","user":"human","action":"pointerdown","target":{"point":[80,12]},"hit":{"role":"input","name":"密码"}}
```

人的操作之所以能进来,是因为**它本来就经过我们**:观看端的输入走
`/channel/cdp`,由我们翻译成 CDP 命令([b §1](b-input.md#1-收口在哪));
页面内再放一个捕获阶段的监听器补上「点中了哪个控件」。

> **这一条是这条路线结构上的收益,不是额外做的功能。**
> 把 CDP 端点直接交给使用者的方案做不到:人在他们的画面里点的那一下,
> 与程序发出的 `Input.dispatchMouseEvent` **在线上是同一种字节**,无从区分。

### 4.1 记控件的身份,不记控件的内容

`hit` 里放的是控件的**标签**(`aria-label` → `<label>` → `placeholder` → `name`),
**不是它的值**。

这不是过度谨慎:早期实现取的是 `innerText || value`,而 `value` 在密码框上就是明文密码,
它会进入日志文件、被日志命令打印、被打包导出。**实测确认过。**

> **行为流天然是一个数据外泄面。** 它记得越细越有用,也越容易记进不该记的东西。
> 判据定成一句话:**记「他动了哪个控件」,不记「控件里是什么」** ——
> 后者要看,有观测和截图,那两条路上有明确的授权。

### 4.2 什么算「一条行为」

**只有改变了远端状态的动作才进这条流。** 页面自身的变化(标题变了、加载状态变了)
不进 —— 没有人「做」它们,那只是同步通知。

这条边界必须守住,否则行为流会退化成事件流,而事件流回答不了
「这一步是谁做的、做了什么」。

## 5. 人一碰就让路

人不需要「申请接管」,**碰一下就是接管**:观看端一有输入即开启让路窗口,
窗口内程序侧的动作直接返回

```jsonc
{"error":{"code":"busy_human","message":"人正在操作",
          "details":{"retry_after_ms":2400}}}
```

只有按下与按键触发让路,**移动和滚轮不触发** —— 否则鼠标一动,
程序侧就会被挡住。

这与常见做法方向相反。其他方案通常要求**显式交接**:程序先声明「我要把控制权
交出去」,人操作完再发一个完成信号。那样做有一个前提 ——
**平台看不见人什么时候动手**,所以只能由程序声明。

我们看得见,因为人的输入本来就经过这一层。于是可以做成隐式的。

**代价要说清楚**:让路窗口是**时间驱动**的 —— 程序只知道「人这会儿没在动」,
不知道「人做完了没有」。对「帮我过一下二次验证」这类场景足够;
对「你看着办,我先去开个会」不够。

> 若要补上「人说完了」,形状应该是**人这一侧一个按钮 + 一条事件**,
> 而不是程序那一侧一个阻塞调用 —— 因为在这里**人随时可以介入,不需要程序允许**,
> 那么「结束」也应由人来说。

## 6. 现在的三个缺口

**① 人打的字,一条都没有。** 观看端输入的中文走 `Input.insertText`,
它**不产生页面 keydown**,而补足「点中了哪个控件」的监听器挂在 keydown 上。
于是「人在这个表单里填了东西」在行为流里**不存在**。

修的方向不是去补那个监听器,而是**换一个记录点**:人的输入本来就经过
我们的翻译层,在那里记录是**由构造保证**的,不依赖页面回报。

**② 「是人还是程序」靠一个时间窗判定。** 我们自己派发动作之后的一小段时间内,
页面报上来的输入都算作我们的。**人在这段时间里点的那一下会消失** ——
不进日志,也不开让路窗口。

记录点换到我们自己的输入层之后,这个问题同样消失:那条连接上来的一定是人。

**③ 没有回放。** 有文字流和单帧截图,没有「点一条跳到那一刻」。
