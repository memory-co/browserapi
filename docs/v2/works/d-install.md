# d · install:一次探清楚,之后不再猜

**一句话**:`install` 的产出**不是「安装完成」,而是一份路径表** ——
后续每次启动 session 均依此执行,不再重复探测,也不再推断。
可下载的下载(浏览器、字体),不可下载的照常安装(X server、xpra),
**判据是该对象属于数据还是程序**,而非是否触碰系统。

## 1. 产出:一份路径表

```jsonc
// ~/.webmuxd.json —— 不是配置文件,而是这台机器的探测结果
{
  "version": 3,
  "at": "2026-08-19T00:19:48Z",

  "browser": {
    "path": "~/.cache/webmuxd/chrome-152.0.7977.42/chrome-linux64/chrome",
    "version": "152.0.7977.42",
    "source": "chrome-for-testing"
  },
  "fonts_dir": "~/.local/share/fonts",        // 下载的字体存放位置

  "xpra": {
    "bin":    "/usr/local/bin/xpra",
    "python": "/usr/bin/python3",             // 由其 shebang 解析得到
    "version": "6.6"
  },
  "xvfb": "/usr/bin/Xvfb"
}
```

每一项都需明确 runtime 的用途:

| 键 | runtime 的用途 | 未固定时的后果 |
| --- | --- | --- |
| `browser.path` | 启动浏览器 | 每次在 `~/.cache` 与 `PATH` 中重新查找 |
| `browser.version` | 锁定版本,变更前需先验证 | 版本变化无法察觉 |
| `fonts_dir` | 判定中文字体是否完备 | — |
| `xpra.bin` | 启动 xpra 进程 | 每次执行 `which xpra` |
| **`xpra.python`** | **探测与安装 PIL 的目标解释器**,非本进程的解释器 | 探测对象错误 —— venv 中可用却被判为不可用 |
| `xvfb` | 传入 `--xvfb=`,**不由发行版配置决定** | 同一命令在不同机器上使用不同的 X server |
| `xpra.version` | 协议兼容性(当前固定使用 rencodeplus) | 旧版本握手失败,报错不指向版本原因 |

**每次重新探测的问题不在于耗时,而在于结果可能与上次不同。** 安装了新的 xpra、
修改了 `PATH`、在 venv 中运行 —— 任一情形都会导致差异,而**报错不会指出
「本次使用的与上次不是同一个」**。将路径固定下来即可消除该类问题。

> 三条既有约束不变:**键存在即探测到,键不存在即未探测到**(不写 `ok:false` 一类空值);
> **显式传入优先**(已指定路径时不读取记录);**记录可能失效**(缓存目录被删除时它无从感知),
> 因此依记录启动,失败即报错**并提示重新执行 install**,不静默重新探测。

## 2. 每样东西从哪来

| | 来源 | 落在哪 |
| --- | --- | --- |
| Chromium | **下载**(Chrome for Testing 的 zip) | `~/.cache/webmuxd/chrome-<版本>/` |
| 中文字体 | **下载** | `~/.local/share/fonts/` |
| chrome 要的系统 `.so` | **系统包** | 系统 |
| Xvfb | **系统包** | 系统 |
| xpra | **系统包**(或用户自己 pip 编译) | 系统 |
| PIL | **pip**,装进 `xpra.python` | 那个解释器 |

判据只有一条:

> **属于数据的下载;属于需要运行且依赖大量系统库的程序的,安装。**

- 字体属于数据 —— 将 `.otf` 放入 `~/.local/share/fonts` 后执行 `fc-cache` 即可,
  **无需 root**(fontconfig 默认包含该目录,已验证)。因此不应经过包管理器。
- Xvfb 属于程序,且**自身动态链接 34 个库**;chrome 直接依赖 **85 个 `.so`**。
  下载 Xvfb 实际等同于下载半个发行版,还需保证与本机 libc 及 X 扩展版本兼容。
  这类对象**只能交由包管理器处理**。

若要将其一并转为下载,唯一途径是自行构建并托管一套自包含产物 ——
这意味着维护一条构建流水线,不在范围内。

## 3. 落地顺序

`install` 共七步,任一步失败均不阻断后续(**尽可能完成全部探测,
最后一次性列出所有缺口**)。

### ① 先看这台机器能不能装

按 `apt-get` / `dnf` / `yum` 的顺序探测包管理器,再判定是否可提权:
**root,或免密码的 `sudo`** —— 需要密码的不计入,`install` 非交互式执行,
阻塞在密码提示上比直接报告无权限更差。

该结果决定后续步骤是**执行安装**还是**仅输出命令**。

### ② 浏览器:测速选源 → 下载 → 解压 → 写标记

```
探几个下载源的吞吐(不是延迟 —— 下一百多 MB 时握手快 20ms 一文不值)
   → 挑最快的那个下载
   → 校验 + 解压到 ~/.cache/webmuxd/chrome-<版本>/
   → 最后写 INSTALLATION_COMPLETE
```

**标记写入是最后一步,而非解压完成即视为成功。** 目录中存在 `chrome` 不代表安装完整 ——
解压中断、磁盘写满、进程被 OOM 终止,均会留下形似完整的文件集合。
**没有标记即视为未安装。**(已验证:目录中仅放置一个已 chmod 的 `chrome`、
其余文件缺失时,旧的判定逻辑仍返回「已安装」。)

失败时**清空该目录**,不保留部分解压结果;并**完整输出**失败原因 ——
DNS 不可达、403、连接超时,三者对应的处理方式各不相同。

### ③ chrome 的系统库:探 → 缺就装

对该二进制执行 `ldd`,标记为 `not found` 的即为缺失项。存在缺失时按 ① 的结论安装整组
(不逐一解析「哪个包提供 libnss3」—— 这需要 `apt-file` / `dnf provides`,
耗时且未必可用;整组安装是幂等的)。

安装后**重新探测一次**。`apt-get` 返回 0 仅表示命令未报错,
**判据始终是探测结果,而非安装器的退出码。**

### ④ 字体:下载,不走包管理器

```
探:fc-list :lang=zh 有没有东西
缺:下载一个 CJK 字体 → ~/.local/share/fonts/ → fc-cache
```

该步骤**不需要 root**,与 ① 的结论无关 —— 无论是否具备权限均可完成。

> 中文字体缺失**不产生错误,仅表现为渲染异常**(显示为方块),
> 是所有项中最容易被误判为缺陷的一个。

### ⑤ xpra 那条腿:xpra / Xvfb

两个都探可执行文件。缺了按 ① 装:

```
Debian/Ubuntu   apt install -y xpra xvfb python3-pil
RHEL/CentOS     yum install -y xpra xorg-x11-server-Xvfb python3-pillow
```

**两个发行版家族的包名均须给出**(`xvfb` 与 `xorg-x11-server-Xvfb`),
只给其一会使另一方需要自行推断。

xpra 在 RHEL 系**不在基础仓库中**,安装失败时须区分「仓库中无该包」与「权限不足」——
前者需添加仓库(给出 xpra.org 的地址),后者需 sudo。**两者的后续处理完全不同。**

### ⑥ PIL:装进 xpra 的那个解释器

`xpra` 是带 shebang 的脚本,读取首行即可得到其解释器。
**PIL 应在该解释器中探测,而非本进程的解释器** —— webmuxd 常运行于 venv,
两者可能完全不同(venv 中缺失而系统中存在时,会误判一个本可运行的模式为不可用)。

无法读取 shebang(例如它是二进制)时跳过该项:**信息不足时不以推断结论阻断流程。**

### ⑦ 把路径写进记录

将前六步解析出的结果一次性写入(§1 的表)。**未探测到的键不写入。**

## 4. 输出长什么样

单屏输出,每行一项,状态置于右侧;存在缺失时,紧随其后给出**可直接复制执行的完整命令**:

```
探测环境…
  python     3.11.2                                 ✓
  包管理     apt-get,可以装                         ✓
  浏览器     chrome 152.0.7977.42                   ✓
  共享库     齐                                     ✓
  中文字体   下好了 → ~/.local/share/fonts          ✓
  xpra       缺 Xvfb                                ⚠
     装上:sudo apt install -y xpra xvfb python3-pil
     不想装的话:webmuxd new … --transport screencast
  记录       ~/.webmuxd.json
```

**具备权限时直接完成安装再报告结果**,而不是仅输出命令 ——
探测到缺失却不处理,等同于将工作原样退回。**仅在无权限时退化为输出命令。**

## 5. 幂等和并发

- **检查与安装是同一个命令**,不需要独立的 `doctor`。重复执行即重新探测。
- **无记录时同样可用** —— `install` 节省的是重复开销,而非作为前置条件。
  以脚本方式使用时不应被一个 CLI 步骤阻断。
- **目录锁尚未实现**:两个终端同时执行 `install` 会相互干扰。
