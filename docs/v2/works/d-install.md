# d · install:下载,不动你的环境

**一句话**:`webmuxd install` 的职责是**把该下的下下来,放进我们自己的目录**;
系统里缺什么就**说清楚该跑哪一行**,但不代你跑。
这台机器不是我们的 —— 有 root 只说明我们**能**改,不说明我们**该**改。

## 1. 这件事比 playwright 难在哪

playwright 的 install 只有一个维度:**把浏览器下下来**。
外加一个显式的 `install-deps`(要 root、只支持 Debian/Ubuntu)去装那些系统库。

我们多出来的是**一整套别人的软件**:

| | playwright | webmuxd |
| --- | --- | --- |
| 浏览器 | 下载 | 下载 |
| 浏览器要的系统库 | `install-deps` | 一样要 |
| 中文字体 | 顺带装 | 一样要 |
| **虚拟显示(X server)** | — | **要**([c §6](c-pixels.md#6-这一套东西是什么)) |
| **一个第三方进程(xpra)** | — | **要** |
| **那个进程自己的 python 依赖** | — | **要,而且要装进它的解释器里** |

多出来的这三行是本质差别:**它们不是我们的软件**。
playwright 的依赖清单是"chromium 跑起来还缺哪些 .so",
我们的清单里有一整个显示服务器和一个跑了二十年的远程显示程序。

还有一条是真机上撞出来的:playwright 的 `install-deps` 只支持 Debian/Ubuntu,
而这套东西经常跑在 RHEL 系的云主机上 —— 那边不光包名不同
(`xorg-x11-server-Xvfb` 而不是 `xvfb`),**连 xpra 默认用的虚拟显示都不一样**。

## 2. 规矩:下载进我们自己的地盘

```
~/.cache/webmuxd/          ← 我们下的东西都在这儿,删掉它等于没装过
~/.webmuxd.json            ← 一份记录,不是配置文件
```

**不动系统。** 不 `apt install`、不 `yum install`、不写 `/usr/`、不改 `/etc/`。

这条要顶住一个很实在的诱惑:**跑起来发现是 root,顺手装一下不就好了**。
不好。理由不是洁癖:

- 一个库在别人的机器上装系统包,**是它的用户没有预期的事**。
  容器里可能没事,别人的开发机上就是事故。
- 装了就要管卸载、管版本冲突、管"我明明没装过这个包"。
  **我们没有能力承担这些,那就不该开这个头。**
- 而且它**做不全**:xpra 在 RHEL 系不在基础源里,再多的自动化也得让人去加源。
  一个"有时候能替你装完、有时候不能"的东西,比"从来不装"更难用。

**唯一的例外是方向,不是行为**:缺什么、该跑哪一行,要说得完整到可以直接粘。

## 3. 于是东西分成三类

| | 谁来 | 有哪些 |
| --- | --- | --- |
| **下载到我们的目录** | 我们 | 浏览器(钉死版本)、中文字体 |
| **装进我们自己的 python** | 我们 | 那些纯 python 的依赖 |
| **只能你来装** | 你 | 虚拟显示、浏览器要的系统 `.so`、xpra 本体 |

第三类要说清**为什么下载不了**,否则看着像偷懒:

- **Xvfb 是个动态链接的 ELF,自己就依赖 34 个库**;
  chrome 直接依赖 **85 个 `.so`**。"下载一个 Xvfb"实际上等于下载半个发行版,
  而且还要保证它和这台机器的 libc、X 扩展版本对得上。
- **xpra 在 PyPI 上只有 sdist,没有 wheel** —— `pip install xpra` 是现场编译,
  要 Cython 和一堆 dev 头文件。**能装成,但那是用户的选择,不该是我们默认替他做的事。**

真要把这些也变成"下载",唯一的路是**我们自己构建并托管一套自包含的产物** ——
那是养一条构建流水线,是比"不发镜像"重得多的承诺,不做。

## 4. 字体:一个从"装"变回"下载"的例子

裸服务器上渲染中文全是豆腐块,这是任何跑无头浏览器的人都会撞上的。
原来的做法是 `apt install fonts-noto-cjk` —— 动系统。

**其实不用。** fontconfig 的默认配置里就有:

```xml
<dir prefix="xdg">fonts</dir>     →  ~/.local/share/fonts
<dir>~/.fonts</dir>
```

把字体文件放进去,`fc-cache` 一下就被认了(实测过,不需要 root)。
于是字体从第三类回到了第一类:**下载一个 .otf,放进用户目录,完事。**

> 这条值得当成一个判据用:**遇到"要装个系统包"的时候,先问一句
> 这东西有没有纯用户态的放法。** 字体有,X server 没有 —— 差别在于
> 前者是数据,后者是要跑起来的程序。

## 5. 探测:探到才叫有

两条规矩,都是撞出来的。

**① 键在 = 探到了,键不在 = 没探到。** 记录里不写 `ok: false` 这种带着理由的空壳 ——
那样每个读它的人都要再判断一次。探不到就是没有这个键,调用方自己决定怎么办。

**② 探的东西必须就是接下来要跑的那个。** 这条不这么写就会踩:

- 探 `Xvfb` 在不在 → 但 xpra 用哪个虚拟显示是**发行版配置**决定的,
  它可能转头去用 Xorg。**探到了也白探**([c §6.1](c-pixels.md#61-虚拟显示钉死-xvfb))
- 探 `import PIL` → 但那是**我们的**解释器,xpra 跑在它自己的解释器上
  (读它的 shebang)。webmuxd 常在 venv 里,两边可以完全不同

> 中间隔着一层别人的配置,探测就只是一句安慰话。

要探的清单:

| 探什么 | 少了会怎样 |
| --- | --- |
| 浏览器下下来了没有 | 起不来 |
| 浏览器缺哪些 `.so` | 起不来,而且报错指向 zygote 不指向缺库 |
| 中文字体 | 中文全是豆腐块 —— **不报错,只是难看**,最容易被当成 bug |
| `xpra` / `Xvfb` 可执行文件 | xpra 那条腿起不来 |
| 跑 xpra 的那个 python 里有没有 PIL | 起到一半死 |
| **服务端有哪些图像编码器** | 只剩 rgb —— **画面能出但带宽爆炸,而且不报错**。还没探 |

最后一行是"能跑但很差"那一类,**比"起不来"难查得多** —— 起不来至少会报错。

## 6. 下载本身的几条规矩

**① 装完了才写标记。** 目录里有个 `chrome` 不等于装完了 ——
解压到一半被 Ctrl-C、磁盘满、进程被 OOM 杀掉,都会留下一堆看着挺像的文件。
所以最后一步写一个 `INSTALLATION_COMPLETE`,**没有它就当没装过**。
(这条是实测出来的:目录里只放一个已 chmod 的 `chrome`、别的全缺,
旧的判断照样说"装好了"。)

**② 失败时把目录删干净**,不留半个解压结果。

**③ 源要测速,而且要能轮换。** 测速解决"慢",轮换解决"挂了" —— 两个问题。
**量的是吞吐不是延迟**:下一百多 MB 的时候,握手快 20 毫秒一文不值。

**④ 幂等。** "检查"和"安装"是同一个命令,不需要一个 `doctor`。
再跑一次就是重新探一遍。

**⑤ 记录不是配置文件。** 它记的是"上次探到了什么",不是"你希望是什么"。
**传进来的赢** —— 显式指定了浏览器路径就不看记录。

## 7. 这条规矩的代价

**裸机上第一次跑默认那条腿会失败**,因为它要的虚拟显示不在。
`install` 会把那一行打出来,但**得你自己跑**:

```
xpra    缺:Xvfb(Debian/Ubuntu:xvfb;RHEL/CentOS:xorg-x11-server-Xvfb)   ⚠
   装上:sudo apt install -y xpra xvfb python3-pil
   不想装的话:webmuxd new … --transport screencast
```

这是"不动你的环境"的价钱,**写在明处**。两条缓解:

- 那一行要**完整到可以直接粘**,而且两个发行版家族都给
- 另一条腿([c](c-pixels.md))零系统依赖,一句 `--transport screencast` 就能走

> **这里有一个真实的张力,不装作没有**:默认走的是需要装东西的那条腿,
> 而 install 又不替你装。两个决定各自都对,合起来意味着**第一次跑可能要多一步**。
> 要么接受这一步,要么改默认 —— 但不能靠"偷偷帮你装"把它抹平。

## 8. 还没定的

| | |
| --- | --- |
| 用 `apt-get install -s` 探依赖 | 比 `ldd` 严格:报包名不报 `.so` 名,而且不用先有浏览器 |
| 目录锁 | 两个终端同时 `install` 现在会互相踩 |
| 探服务端的图像编码器(§5) | "能跑但很差"那一类 |
