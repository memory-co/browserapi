# rrweb 控制台:整屏重放,只读;输入全走 CDP

```bash
python3 examples/rrweb_console/serve.py --port 8090
python3 examples/rrweb_console/serve.py --port 8090 --url https://www.bilibili.com/
# 打开 http://<这台机器>:8090/
```

整块画面就是 rrweb 重放出来的 DOM。默认先打开一个**自检页**(`/demo`),
五格分别验鼠标、中文输入、光标形状、滚动、只读。

## 只读是结构性的,不是靠自觉

重放出来的那棵 DOM 整个 `pointer-events: none` —— **点不到、选不中、链接也点不开**。
所有事件都落在它上面那层透明的接收层上,由接收层翻译成 CDP 调用。
代码里**没有任何一条路把事件送进重放出来的 DOM**。

```
你的鼠标/键盘 → 接收层 → WS → Input.dispatchMouseEvent / insertText → 真正那个 tab
                                → 页面变了 → rrweb 事件 → 画面跟着变
```

这就是设计里那条:**画面来源可以有多条,输入永远只有一条**
([b §1](../../docs/v2/works/b-input.md#1-收口在哪))。
画面换成截屏、换成 xpra,上面这条路一个字都不用改。

## 三件事归 CDP,rrweb 一件都不碰

| | 怎么来的 |
| --- | --- |
| **鼠标位置** | 接收层按舞台缩放比换算回页面坐标 → `Input.dispatchMouseEvent` |
| **光标形状** | 页面内探针报 `getComputedStyle(el).cursor`,**过白名单**再写进观看端 |
| **文字 / IME** | 组字全程在本地,`compositionend` 之后才 `Input.insertText` |

光标那条按设计稿的白名单来([b §5](../../docs/v2/works/b-input.md#5-光标同步)):
取值会写进观看端的 `style.cursor`,而远端页面不可信,所以**只认那三十来个 CSS 关键字,
其余一律降级 `default`**。自检页第 ③ 格最后一个是 `url(...)` 自定义光标,
实测确实降成了 `default`。

组字期间**一个按键都不往外发** —— 否则远端会收到一串无意义的字母。

## 资源:全部经本服务转发

图片、字体、样式表、普通视频一律改写成 `/res?u=…`。手上有就给,没有就带着
`Referer`/UA 去上游取一份,**取不到才 302 回原地址**(退回去不比不做代理更差)。

不这么做的话,重放端要自己回原站拉 —— 实测 B 站那一页 30 张图破 25 张,
因为它的 CDN 认 `Referer`。转发之后 25 张走代理、只剩 5 张破。

> **但 MSE / `blob:` 的视频画面拿不到。** 那不是地址问题,是**根本没有地址** ——
> 画面在浏览器内存里由 MediaSource 拼出来,rrweb 记的是元素和播放位置、不是帧。
> B 站的播放器在重放里是一块黑的,而播放器的控件、"试看30秒"那层提示都在(它们是 DOM)。
> 要那块画面只能传帧,而传帧就是截屏那条腿
> ([c §13.1](../../docs/v2/works/c-pixels.md#131-rrweb是一条来源但代价买不起))。

## 实测(自检页,2026-08-20)

| 验什么 | 结果 |
| --- | --- |
| 点按钮 | 真页面收到,**重放画面跟着变** |
| 中文输入 | `hello 世界` 进了输入框,重放里也看得到 |
| 光标 `pointer` / `text` | 跟着变 |
| 光标 `url(...)` 自定义 | **降级 `default`** |
| 延迟 | **0.0s** |
| 只读 | 重放的 iframe 与 wrapper 的 `pointer-events` 实测都是 `none` |

## 挡路的对话框:不接管就等于整个会话冻住

**这是实际用起来最先撞上的问题,而且症状是"鼠标点了没反应"。**

开了 `Page.enable` 之后,Chrome 把 JS 对话框交给客户端**并一直等**。
没人应答的话渲染进程就卡在那儿,之后每一个 `Input.dispatchMouseEvent` /
`Page.navigate` 都排在后面,三十秒超时。实测:

```
alert 弹出之前:CDP 往返 3 ms
alert 弹出之后:连着三次十二秒都不回
```

真实场景里最容易触发的是 `beforeunload` —— 在页面上点过东西再想离开就会弹,
一弹就永久卡住。

所以这里接管了 `Page.javascriptDialogOpening`:弹一张卡片给你选,
**25 秒没人答就自动取消**(不替使用者决定,但绝不允许永久卡住,
[g §3](../../docs/v2/works/g-native-ui.md))。
指令超时也会在顶栏显示出来 —— 只写日志的话,使用者看到的只是"点了没反应"。

## 三个坑,都是"不报错但不工作"那一类

**① live 的基线必须是「现在」,不是快照的时间戳。**
rrweb 的 live 模式按 `事件时间 − 基线` 排期。基线取快照那一刻的话,只要快照是
十秒前拍的(重连、或者页面静止了一会儿),后面每一条新事件都会被排到十秒后才应用 ——
表现就是**点了没反应,而且不报错**。用 `Date.now()`:陈旧的立刻补上,新的实时应用。

**② 注入脚本会自我递归。** `addScriptToEvaluateOnNewDocument` 对每一个新文档生效,
包括 rrweb 自己造的 `about:blank` iframe —— 被注入的 iframe 又造 iframe,
实测每秒新建二十来个,主页面的全量快照直接被饿死。
必须挡两道:只在顶层、只在 `http(s)` 页面上录。

**③ 给 rrweb 一个专属容器。** 处理 Meta 事件时要清掉上一轮的重放,
第一版写的是"删掉舞台里除了接收层和输入框之外的所有孩子" ——
后来加的对话框卡片就被一起删了,**而且不报错,只是永远不出现**。
换成 rrweb 独占一个 `#paintbox`、只清那个容器,叠在上面的东西再多也不会被误伤。

**④ UMD 后面要跟分号。** rrweb 的 bundle 最后一行是 `}))`,后面直接接 `(() => …)()`
会被当成"调用上一个表达式的结果",报 `(intermediate value)(...) is not a function`。

排查这类问题得能分清「输入没进去」和「画面没更新」—— 两者表现一模一样,修法完全不同。
`/probe?e=<js>` 就是干这个的:**照直问真页面**。

## 已知的粗糙处

- 只跟一个 tab;页面新开的 tab 不进重放
- 视口钉死 1280×800(`Emulation.setDeviceMetricsOverride`),没做跟随窗口
- 事件缓冲上限 8000 条,超了砍一半 —— 长时间跑会丢历史(实时看不受影响)
- `/probe` 是排查用的,**它能在页面里执行任意 JS**,不该出现在真产品里
- 资源缓存在内存,不设上限之外没有淘汰
- chrome 是这个服务的子进程,`Ctrl-C` 和 `kill` 都会关干净
